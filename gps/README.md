# GPS-ENGINE-001 — движок расчёта обработанной площади

Первый кодовый инкремент трека «GPS план-факт». Считает, сколько гектаров
машина фактически обработала за интервал, и выдаёт вместе с цифрой флаг
качества трека.

Пакет **не является частью Flask-приложения**. Он не импортирует ни `app`,
ни `models`, не открывает `transport.db` и держит свой `requirements.txt` —
по тому же правилу, что и `drone_collector`: служба не должна тащить
numpy/scipy из-за модуля, который она не импортирует.

---

## Метод

```
точки интервала
  → фильтр: скорость 1–15 км/ч
  → сгущение пути каждые 5 м (только сегменты короче 150 м)
  → альфа-форма: триангуляция Делоне, треугольники с радиусом
    описанной окружности < альфа
  → объединение треугольников
  → отдельные куски объединения = участки работы; куски меньше порога — проезд
  → площадь в UTM 41N (EPSG:32641)
```

### Геозона методу не нужна — изменено 12.08.2026

Операторы на местах геозоны обычно **не заводят**: обводят трек по периметру
обработки вручную и записывают цифру. Метод, считавший только внутри
заведённого полигона, поэтому терял всё, что никто не завёл: на наборе по
опрыскиванию это **31,77 га из 159**, и две работы из пятнадцати выходили
ровным нулём, пока трактор весь день был в поле.

| вариант | медиана \|расхождения\| |
|---|---|
| с обрезкой по контуру, альфа 10 м | 26,4% |
| с обрезкой по контуру, адаптивная альфа | 12,0% |
| **без контура, участки по треку** | **6,9%** |

Работа 08.08 была −100%, стала +2,4%; 05.08 была −92,3%, стала +10,1%.

`work_sites()` — основной вход. Геозона, если она есть, только **называет**
участок для счёта: не фильтрует и не обрезает. `worked_area()` остаётся для
случая, когда вопрос задан про конкретный контур.

Параметры — константы, а не настройки. Метод зафиксирован письменно
2026-07-29 и проверен на наборе, которого он не видел: медиана расхождения с
ручным замером владельца **3,3%** на 17 работах. Каждое число измерено, а не
выбрано: точки вдоль прохода стоят через 35–55 м, соседние проходы — через
5–14 м, и именно этот разрыв масштабов делал параметр хрупким. Сгущение
убирает разрыв, после чего альфа устойчива в диапазоне 8–15 м.

### Адаптивная альфа — введена 12.08.2026

Правило `альфа = max(10; 1,2 × измеренный шаг проходов)` было записано
29.07 и тогда **не принято**: оно подобрано на тех же 17 работах, которые
улучшало. Предрегистрация говорила — правило входит в метод, только если
подтвердится на невиданном наборе. Набор пришёл 12.08: 15 ручных замеров по
опрыскиванию, расчёт замороженным кодом, закоммиченным **до** данных.

| | медиана \|расхождения\| | среднее |
|---|---|---|
| фиксированная альфа 10 м | 26,4% | −32,1% |
| адаптивная | **12,0%** | −22,9% |
| адаптивная, 8 работ без неразмеченной земли и рваного трека | **3,4%** | — |

Устойчивость проверена по обоим параметрам оценщика: признак «другой
проход» (отношение 3 / 5 / 8) не меняет результат вообще, множитель
1,1 / 1,2 / 1,3 двигает медиану в пределах 10,1–12,0%.

И правило **ничего не портит там, где метод уже подтверждён**. У
опрыскивателя шаг 13–22 м, у культиватора 5–9 м, поэтому `max(10; 1,2×8)`
даёт те же 10 — на культивации правило математически холостое. Проверено
переигровкой: калибровочный набор 18–23.07 сдвигается **ровно на +0,0%**
(ни одна работа не изменилась), набор 27.07 — на +0,9%, и все сдвинувшиеся
работы там опрыскивание.

Чтобы воспроизвести старое поведение точно, передайте `alpha_m=ALPHA_M`.

**Чего набор не закрыл:** 7 работ из 15 остаются неверными по причинам, к
альфе не относящимся — до 8,8 га обработано по земле, на которой вообще нет
геозоны, и треки теряют до 708 минут движения в сутки. Это дефекты входных
данных; движок их измеряет и показывает, но исправить не может.

**Контур определяется только по треку** — какие полигоны содержат точки
машины. По имени нельзя: справочник Wialon содержит дубли по конструкции,
«1508 Нурхон Бобохон» существует двумя зонами (4,32 и 8,97 га), и поиск по
точному имени однажды выбрал ту, где трактора не было ни одной точкой.

## Чего движок не делает

В нём **нет бизнес-правил**. Он не решает, что считать работой, а что
проездом; какое расхождение допустимо; когда трек слишком рваный, чтобы
выставлять счёт. Это решения владельца (вопросы В-2 и В-3 в
`docs/GPS_PLAN_FAKT_VISION_ROADMAP.md`). Движок возвращает измеренные числа,
пороги накладывает вызывающий код.

## Как проверен

**Синтетика** — ответ известен по построению: квадрат 100×100 м, пройденный
проходами через 5 м, даёт 0,9875 га (недобор 1,25% — граничный эффект
альфа-формы, свойство метода); необработанная полоса 30 м не заклеивается;
разрыв 240 м не сшивается; проезд на 30 км/ч даёт 0 га; вырез в контуре
шириной 3 м не попадает в площадь.

**Реальная фикстура** — зона 3208 и трек юнита 3464 за 27.07.2026:
воспроизводится записанная цифра **8,51 га** при 939 рабочих точках, и
соседняя зона-однофамилец даёт ноль (отрицательный контроль опознания
контура по треку).

**Метрика качества трека переписана трижды, и каждый раз ошибку находило
измерение, а не рассуждение.** Считать разрывы по всем сообщениям — стоянка
становится «рваным треком» (26 ложных разрывов у юнита 3068). Считать по
подряд идущим движущимся точкам — стоянка возвращается, потому что сообщения
между ними не смотрят (23 ложных разрыва и 5,9 «потерянных» часа у юнита 3464
при полностью целом треке). Требовать движения на любом из концов разрыва —
считается ночная стоянка: трактор встал, двигатель заглушен, трекер уснул, а
утреннее сообщение показывает движение (708 «потерянных» минут у юнита 1729
за 05.08, где все 13 разрывов начинались на нуле).

Верно: разрыв — это молчание трекера **на ходу**, то есть скорость в
последней точке перед провалом больше нуля. По всем 37 машино-дням остаётся
5 настоящих разрывов на 126 минут против 56 стоянок на 3777 минут, которые
считало прежнее правило.

Проверено на трёх реальных треках: у 3068 наивный счёт 26 → верный 0, у 7242
5 → 0, у 1729 за 08.08 наивных 14, а настоящий ровно один — 52 минуты
молчания на ходу. Метрика, всегда возвращающая ноль, прошла бы первые две
строки и провалила третью.

**Мутационная проверка** (2026-08-12) — набор обязан ловить порчу движка.
Одиннадцать мутаций, каждая поймана:

| Мутация | Упало тестов |
|---|---|
| сгущение выключено | 8 |
| альфа раздута до 100 м | 6 |
| верхняя граница скорости 100 км/ч | 1 |
| метрика разрывов возвращена к наивной | 2 |
| обрезка по контуру убрана | 1 |
| нижняя граница скорости 0 (холостой ход) | 4 |
| фильтр «внутри контура» убран | 1 |
| множитель альфы 1,2 → 1,0 | 1 |
| шаг проходов игнорируется (всегда альфа 10) | 4 |
| оценщик берёт максимум вместо медианы | 5 |
| признак «другой проход» выключен | 1 |

**Дважды мутации ловили один и тот же дефект набора: ожидание, записанное
через саму константу, уезжает вместе с мутацией.** Так тест проезда
(`SPEED_MAX_KMH + 15`) и тест альфы (`ALPHA_SPACING_FACTOR * 14`) молча
проходили на испорченном коде. Оба переписаны на литералы — 30 км/ч и 16,8 м.
Ещё одна мутация (обрезка по контуру) не ловилась ничем — добавлен тест
контура с вырезом.
