# DRONE-USEFUL-AREA-PILOT-001 — операторский комплект

Контролируемый пилот расчётной полезной площади на **площадке**. Один день —
**2026-06-05**, один проверенный коммит — `c3e6a12ab95117710eeea5e05133f5cd548b698e`
(merge PR #113; head функциональной ветки внутри него — `82b3a2f`).

**Production не участвует.** Ни один скрипт комплекта не пишет в
`C:\transport-report`, не останавливает `TransportReport`, не применяет
миграцию к продовой базе и не обращается к `http://10.103.25.14:5050`.
Продовую базу трогает ровно один шаг — предполётный, — и только как
**источник онлайн-бэкапа**: `backup_transport_db.py --source`, тот самый
механизм, который каждую ночь снимает копию по расписанию.

## Порядок для владельца

Каждый блок выполняется **целиком**, одним куском. Скрипты останавливаются на
первом же расхождении и печатают, где именно они остановились.

### Блок 1 — предполётная проверка и миграция на копии

```
Set-Location C:\transport-report-staging
.\ops\pilot_useful_area_001\PREFLIGHT_AND_COPY_TEST.ps1
```

**Вернуть в чат:** весь вывод консоли и путь из строки `EVIDENCE=`.
Ключевые строки: `STAGING_SERVICE=`, `COPY=`, `COPY_AREA_SHA256=`,
`COPY_AFTER_AREA_SHA256=`, `PREFLIGHT_AND_COPY_TEST=PASS`.

**Не идти дальше**, если два отпечатка `area_ha` различаются или строки
`PASS` нет.

### Блок 2 — обновление и миграция площадки

```
Set-Location C:\transport-report-staging
.\ops\pilot_useful_area_001\STAGING_DEPLOY_AND_MIGRATE.ps1
```

**Вернуть в чат:** весь вывод и строки `BACKUP=`, `MANIFEST=`, `SHA_AFTER=`,
`SMOKE_TEST_STATUS=`, `STAGING_DEPLOY_AND_MIGRATE=PASS`.

Если блок отказал — откат:

```
Set-Location C:\transport-report-staging
.\ops\pilot_useful_area_001\STAGING_ROLLBACK.ps1
```

### Блок 3 — живой сбор DJI (на BAK-TEX11)

```
Set-Location C:\VehicleSoft_DJI_StageB_Pilot
.\ops\pilot_useful_area_001\BAK_TEX11_DJI_COLLECT_TO_STAGING.ps1
```

Откроется браузер. В нём: Task History → **день 2026-06-05** → вид «Карта» →
дождаться прорисовки маршрутов → вернуться в консоль и нажать Enter.

**Вернуть в чат:** весь вывод консоли и **файл** из строки `EVIDENCE=`.
Этот один json-файл надо перенести на сервер — он нужен блоку 5.

**Журнал прогона (`RUN_LOG_SLICE=`) остаётся на BAK-TEX11.** В безопасный
отчёт он не входит и в чат не отправляется.

### Блок 4 — пересчёт на площадке

```
Set-Location C:\transport-report-staging
.\ops\pilot_useful_area_001\STAGING_RECALCULATE_AND_VERIFY.ps1
```

**Вернуть в чат:** весь вывод, включая `APPLY_SECONDS=`, `SECOND_APPLY ...`,
`AREA_SHA256_BEFORE/AFTER`, `STAGING_RECALCULATE_AND_VERIFY=PASS`.

Затем открыть глазами и сказать, что видно:

```
http://10.103.25.14:5051/drones/coverage?date_from=2026-06-05&date_to=2026-06-05
```

### Блок 5 — итоговый безопасный отчёт

`<путь>` — файл, принесённый из блока 3.

```
Set-Location C:\transport-report-staging
.\ops\pilot_useful_area_001\STAGING_PILOT_REPORT.ps1 -CollectEvidence <путь>
```

**Вернуть в чат:** строки `VERDICT=`, `REASON=`, `PRIVACY_SCAN=` и **оба
файла** `PILOT_REPORT.json` и `PILOT_REPORT.md`.

## Чего комплект НЕ решает

Три показателя задания схема `DRONES_USEFUL_AREA_001` **не хранит**, и они
остаются в отчёте `null` с кодом `NOT_RECORDED_BY_SCHEMA`:

| Показатель | Почему | Что стоит рядом честного |
|---|---|---|
| число исключённых полностью холостых **вылетов** | признак хранится на уровне работы, а не вылета | `works_with_zero_work_segments` |
| число **смешанных вылетов** | `mission_state` хранится на работу, а не на вылет | `works_with_mixed_mission_state` |
| число отрезков **холостого перелёта** | схема хранит `work_segments`, но не общее число отрезков | `work_segments` |

Посчитать их можно только новой колонкой или вторым разбором геометрии —
то есть новой функцией продукта, которую этот макроэтап запрещает. Число не
выдумано; поле названо пустым.

**Порог `-AdjustShareThreshold` (по умолчанию 0.20)** — параметр отчёта,
выбранный сессией, а не бизнес-правило. Отчёт всегда печатает и порог, и сырую
долю, так что вердикт пересчитывается глазами. Правильную границу называет
владелец.

**Отклонение полезной площади от площади DJI не судится автоматически.**
Никакое правило «сколько процентов — это нормально» не доказано, поэтому в
отчёте стоит код `DJI_DELTA_NOT_AUTOJUDGED`. Если владелец назовёт границу,
она передаётся как `-DjiDeltaAdjustPercent <число>`.

**День выбирает оператор в браузере.** У режима `--route-ui-collect` нет
`--from/--to`: день — это тот, который открыт в кабинете. Держит день не флаг,
а проверка на площадке: блок 4 отказывается считать, если хоть один принятый
маршрут принадлежит другим локальным суткам.
