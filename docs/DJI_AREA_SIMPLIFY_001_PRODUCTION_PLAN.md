# DJI-AREA-SIMPLIFY-001 — минимальный план постоянной работы

План, а не реализация. Исполняется **после** holdout и только при его `PASS`;
при `FAIL` или найденном повторяемом пропуске правила пункты 1–3 откладываются, а
отчётность остаётся на RAW с видимой нерешённой экспозицией.

## Что остаётся неизменным

- **RAW DJI неизменяем.** `drone_flights.area_ha` не читается и не пишется слоем
  площади ни сейчас, ни после. Исключение — это отдельная величина рядом, а не
  правка числа.
- **Новых таблиц нет.** Всё нужное уже лежит в восьми таблицах `dji_*`
  (`DJI_AREA_EVIDENCE_001`).
- **Нового движка нет.** Кандидата называет `dji_area/structural.py`, статус —
  `dji_area/resolver.py`, класс — `dji_area/accounting.py`.
- **Биллинг не меняется.** `billable_area_m2` остаётся NULL до отдельного решения
  владельца.
- **Движок покрытия заморожен** как аудиторский слой: `dji_area/coverage.py` и
  `tools/dji_area_block1b.py` остаются инструментом разбора по требованию и в
  ежедневный путь не входят. На борту без канала распыления (3 Gijduvon, 10,7 %
  площади августа) он принципиально ничего не подтверждает.

## Четыре инкремента

| # | Что | Где | Схема | Размер |
|---|---|---|---|---|
| 1 | Адресный сбор V4 | сборщик + один read-only endpoint | без изменений | малый |
| 2 | Статус записи | чтение `dji_area_calculations` | без изменений | готово |
| 3 | RAW / исключено / corrected рядом | отчёт `/drones/area-evidence` и его книга | без изменений | малый |
| 4 | Ежедневный пересчёт | Scheduled Task | без изменений | конфигурация |

### 1. Адресный сбор V4

Сборщик уже умеет `--sources --ids-file`; не хватает только списка. Сборщик к базе
не ходит по построению, поэтому список отдаёт приложение — read-only endpoint по
образцу `/drones/api/land_geometry_manifest`:

`POST /drones/api/area_capture_manifest` → идентификаторы вылетов последних трёх
дней, которые (а) кандидаты замороженного экрана или (б) попали в малую случайную
контрольную выборку, и у которых ещё нет ревизии V4. Отбор — та же функция
`build_plan`, что исполнила holdout, без фиксации плана.

Объём по августу: около 14 кандидатов и 10 контрольных записей в сутки — 25
посещений, около пяти минут, против 270 посещений и 50 минут при сборе всего
парка. Контрольная выборка нужна постоянно: она единственное, что заметит новый
класс аномалии, которого правило не знает.

Запись без V4 у DJI (`NO_V4_AT_SOURCE`) остаётся `PHANTOM_STRUCTURAL` навсегда и
видна отдельной строкой; в августе таких было 3 из 428.

### 2. Статус записи

Ничего хранить не нужно. Класс — чистая функция строки расчёта:
`dji_area.accounting.classify(row)`. Строка уже несёт статус резолвера, право на
агрегирование, признаки экрана и флаги, и она append-only с версией алгоритма.

| Класс | Откуда берётся | Что показывается |
|---|---|---|
| `NORMAL` | счётчик подтвердил RAW, либо V4 нет и подозрений нет | RAW |
| `PHANTOM_PROVEN` | проверенное окно счётчика, статус завышения, `CERTIFIED` | проверенный прирост, включая 0 |
| `PHANTOM_STRUCTURAL` | кандидат экрана с совпавшим скаляром, проверенного интервала нет | RAW, помечен; **не обнуляется** |
| `REVIEW` | пересечение интервалов, выброс счётчика, применение при плоском счётчике, неизвестный статус | RAW, помечен; без автокоррекции |

Отдельная колонка в базе понадобится, только если класс начнёт фильтроваться SQL-ом
на больших периодах. Это аддитивная миграция, и она не нужна заранее.

### 3. RAW / исключено / corrected рядом

Страница `/drones/area-evidence` уже показывает «DJI RAW», «Проверено»,
«Предварительно», «Недостаточно данных» и число «Повторных/перенесённых». К ним
добавляются четыре величины из `accounting.summarize` и таблица по бортам:

- подтверждённо исключено, га (и сколько записей);
- ждёт проверки V4 — `PHANTOM_STRUCTURAL`, га;
- на разборе — `REVIEW`, га;
- RAW минус подтверждённое — справочно, с подписью, что нерешённое внутри по RAW.

Существующая выгрузка вылетов (`drones_flights_<от>_<до>.xlsx`) **не меняется**:
её колонки уходят операторам и в бухгалтерию. Класс записи и исключённая площадь —
это книга отчёта площади, а не выгрузка вылетов.

Строки интерфейса двуязычны, узбекский — кириллицей; ключи через словарь, иначе
сработает проверка `t-key-missing`.

### 4. Ежедневный пересчёт

Одна задача планировщика, три вызова подряд: вылеты → источники по манифесту →
`tools/dji_area_recalc.py --from <три дня назад> --to <сегодня> --apply`. Пересчёт
идемпотентен: тот же вход даёт `unchanged`.

## Решения, которые остаются за владельцем

Код их не принимает и не должен.

1. Можно ли `PHANTOM_STRUCTURAL` исключать предварительно, до прихода V4. Сейчас —
   нет, по действующему правилу проекта. В августе правило не ошиблось ни разу
   (428 из 428), но это довод для решения, а не само решение.
2. Исключаются ли вместе с площадью литры. У записи-фантома литры равны сумме
   литров базового вылета и ручного мостика, то есть тоже задвоены (4,99 % за
   август).
3. Когда исключённая площадь выходит из теневого режима в расчёты с операторами.
4. Норматив междурядья. Это единственный рычаг площади, который не видит ни
   счётчик, ни телеметрия: у 13 Peshku в августе среднее 7,5 м при 6,0–6,5 м у
   остального парка.
