# DRONE-AREA — канонический план и реестр утверждений

**Это единственный источник истины по задаче площади дронов.** Ни одна из
сторон не пишет конкурирующий план в другом месте. План меняется только
дельтой в конец файла — с датой, автором и ссылкой на артефакт.

Состояние трека дронов в целом — `docs/tracks/drones.md`. Здесь только
площадь.

Зафиксировано 10.09.2026 по итогам согласования владелец / ChatGPT / Claude
Code. Переговорная фаза закрыта.

---

## 1. Роли

| Сторона | Отвечает | Не делает |
| --- | --- | --- |
| **Владелец** | бизнес-метрика, допустимый tolerance, полевой эксперимент, production/deployment | не арбитр технических споров |
| **ChatGPT** | постановка задачи, критерий доказательности, внешние DJI и нормативные источники, независимый review кода и результатов, попытка опровергнуть | не строит параллельную реализацию |
| **Claude Code** | репозиторий, база, V4, эксперименты, реализация, тесты, evidence bundle, обязательный self-adversarial прогон | не выдумывает бизнес-правила; не финальный ревьюер собственного кода |

**Связь.** Прямого канала между моделями нет. ChatGPT пробовал создать GitHub
Issue и получил `403 Resource not accessible by integration`: чтение
репозитория есть, записи нет. Поэтому канал односторонний — Claude пишет в
репозиторий, ChatGPT читает сам, владелец передаёт только короткий verdict.

## 2. Правила протокола

1. Каждое утверждение имеет тип: **ФАКТ** (обязательна ссылка — `file:line`,
   результат запроса или URL), **ПОДДЕРЖАНО**, **ГИПОТЕЗА**, **ОСЛАБЛЕНО**,
   **ОПРОВЕРГНУТО**, **ОТКРЫТЫЙ ВОПРОС**. Без ссылки ФАКТ не принимается ни
   от кого.
2. Расхождение закрывается артефактом, а не аргументом. Проигрывает сторона,
   у которой артефакта нет, независимо от убедительности.
3. **Ни одна сторона не переводит собственное утверждение в ДОКАЗАНО.** Для
   этого нужен заранее сформулированный тест на опровержение, который был
   проведён и не опроверг, плюс независимое подтверждение. «Возражений не
   нашли» — это ПОДДЕРЖАНО, а не ДОКАЗАНО.
4. Один активный макроэтап. Пока он не закрыт, новых планов не пишет никто.

## 3. Разные величины, которые нельзя смешивать

| Величина | Что это | Когда известна |
| --- | --- | --- |
| `FIELD_AREA` / `totalArea` | геометрия нарисованного контура | всегда |
| `TASK_AREA` / каталожный `workArea` | плановая рабочая область после исключений | **до вылета** |
| `DJI_RAW_RECORDED_AREA` / `new_work_area` | что записал DJI | после вылета |
| `DJI_CORRECTED_RECORDED_AREA` | техническая коррекция записи DJI | после расчёта |
| `V4_APPLICATION_COVERAGE_ESTIMATE` | уникальная поверхность под подтверждённым применением | цель этапа 1 |
| `VERIFIED_UNIQUE_APPLICATION_AREA` | то же после физической калибровки и holdout | цель этапа 3 |
| `BILLABLE_AREA` | договорное число | отдельным решением владельца |

Правила, принятые обеими сторонами:

- `Task Area` — **плановая** величина. Официально: «displays the value of the
  actual area of the **planned task route after planning the field**»
  (руководство Agras T30 v1.4). Она не меняется, если дрон обработал часть
  поля, и полностью задаётся оператором при планировании (граница,
  препятствия, отступ). Биллинг по ней — оплата за рисование.
- `Obstacle Area` — это **препятствия внутри контура**, а не холостые
  перелёты. Вычитание её холостой ход не убирает.
- Фантомная запись **не вычитается**. Она теряет право быть источником
  истины, а вклад интервала восстанавливается независимо по V4.
- **Прямая линия ≠ холостой полёт.** Правило `gap_m = 60 м` уже стоило
  проекту неверного результата: 103 из 103 длинных прямых отрезков внутри
  контура оказались настоящими проходами (`docs/DJI_AREA_48H_DECISION.md` §10,
  коммит `a5dc4e6`). Для точек маршрута (упрощённая ломаная) разрыва по
  расстоянию нет вовсе. Для кадров V4 — телеметрия ~1 Гц — разрыв есть, и он
  проверяется временем и физической скоростью, а не длиной.

## 4. План: три макроэтапа

**Этап 1 — FIRST INDEPENDENT V4 APPLICATION COVERAGE.** Блок 1A — код в
чистом репозитории. Блок 1B — прогон на реальных данных сервера. Результат:
первая воспроизводимая карта и число для дронов №5 и №6 за 18.08.2026.
Называется `V4_APPLICATION_COVERAGE_ESTIMATE`, не billable.

**Этап 2 — физическая калибровка.** Один участок, независимо измеренная
геометрия, водочувствительные карточки по методике NY/T 3213—2023 (граница
полосы по плотности не менее 20 капель/см², шаг не более 0.2 м, не менее трёх
повторов). Специально созданные: нормальный проход, перекрытие, край поля,
пауза/возобновление, дозаправка, перелёт без распыления, ручное распыление и
**намеренно завышенное междурядье**.

Последнее — не про точность, а про antifraud. Междурядье задаёт оператор, и
площадь линейно от него зависит; при завышении дозатор льёт пропорционально
шире, поэтому расход на гектар остаётся константой и контроль «литры на га»
манипуляцию не видит. Ловят её только карточки.

**Этап 3 — заморозка, слепой holdout, продукт.** Версия и параметры
фиксируются. Невиданный период, несколько аппаратов, выборка и прогноз
фиксируются до вскрытия, подгонки после просмотра нет. Отдельно оцениваются
нормальные случаи, дубли/stale, ручной режим и возобновление, недостаточное
evidence. Только после этого — паспорт работы, очередь исключений и отдельным
решением правило `BILLABLE_AREA`.

- **10.09.2026, ChatGPT (review) + Claude Code (правка), exporter 1B.**
  Consolidated review нашёл в инструменте выгрузки шесть замечаний, два
  блокирующих; оба подтверждены на закоммиченном коде и исправлены.
  (1) Сводка V4 бралась связью по `flight_id`, который в
  `dji_v4_summaries` НЕ уникален — уникален `source_revision_id`. Теперь
  `v.id = c.v4_summary_id`, то есть та сводка, которую назвал сам расчёт.

  дубль строки. (2) Историческая идентичность контура не выгружалась вовсе,
  и брались все ревизии по `land_uuid` — прямое нарушение пункта A11.
  Теперь выгружаются `land_snapshot_id`, `land_revision_id`,
  `historical_geometry_sha256`, ревизия атрибуции помечена
  `USED_BY_ATTRIBUTION` отдельно от прочих, а при недоказанной исторической
  геометрии вывод — `UNKNOWN_CURRENT_SNAPSHOT_ONLY`. (3) Bundle стал
  самодостаточным: неизменяемые тела V4, маршрутов и геометрии полей
  выгружаются с проверкой SHA/MD5 и манифестом, расчёт воспроизводится без
  доступа к серверу. (4) `total − obstacle − work` вынесен как
  `unexplained_exclusion_ha` и НЕ называется safety margin. (5) Все выборки
  идут в одной read-транзакции; непустой каталог вывода останавливает
  прогон. (6) `implied_speed` переименована в `min_required_speed_m_s`:
  знаменатель включает время без обработки, поэтому величина
  фальсифицирует запись только сверху и ничего не подтверждает снизу.
  Замечание про `S` относилось к черновику из scratchpad: в
  `dji_area/coverage.py` S с самого начала считается как
  `сумма(ширина_i × расстояние_i)` по кадрам, а не через `width_max`.
