# Трек: UI/UX

Точка входа трека. Новая сессия читает **этот файл первым**, дальше — по
ссылкам. Полная процедура работы — `docs/ux/00-workflow.md`.

## 1. Цель и границы трека

Довести интерфейс до состояния, в котором одна и та же функция выглядит и
ведёт себя одинаково во всех модулях, и **закрыть путь обхода дизайн-системы**,
которым эта одинаковость разрушалась до сих пор. Функциональность не меняется:
трек не трогает бизнес-правила, схему БД и деловое содержание выгрузок.

**Не входит:** новые экраны и новые отчёты; изменение смысла колонок Excel/PDF;
`_perform_fuel_sync`; миграции (у трека их быть не должно — необходимость
миграции означает выход за границы); проектирование Telegram Mini App
(заморожено по CLAUDE.md); визуализация данных (её в продукте нет — заводить
или нет, отдельное решение владельца, см. `docs/ux/00-workflow.md` §14 P3).

**Тёмная тема — больше не «вне объёма», решение перенесено на гейт P3.**
Владелец сообщил 2026-08-09, что планирует Telegram Mini App со всей
функциональностью по ролям и правам. Mini App — это webview: он рендерит тот
же HTML и CSS, а по соглашению Telegram наследует тему пользователя, включая
тёмную. Сейчас 90 токенов — плоские hex в одном `:root`. Заложить два набора
в архитектуру токенов дёшево; ретрофитить тёмную тему в уже разошедшиеся
значения плюс 213 хардкод-цветов — работа другого порядка. Проектирование
самого Mini App в трек по-прежнему не входит.

**Общие файлы.** Трек по определению правит `templates/base_next.html` и
`static/css/design-system.css` — оба в списке общих. Это объявление соседним
трекам (Дроны, АЗС, Запчасти, GPS): планируйте правки этих двух файлов с
оглядкой на трек UI, конфликты слияния наиболее вероятны здесь.

### Следующий шаг, описанный точно

**Ничего не делать до подписи владельца.** Работа P4 закончена; открыт
только гейт.

Владельцу смотреть `docs/ux/50-canonical/index.html` — лист сравнения, слева
код до трека, справа рабочее дерево, фикстуры одни и те же. Подпись
ставится в `docs/ux/32-canonical-screens.md` §7.

Что подпись означает: набор оснований принят, и дальше распространение на
остальные модули идёт **механически** — задача миграции формулируется как
«привести модуль к контрактам §6 спецификации», а не «улучшить дизайн
модуля».

**После подписи начинается P5** (`docs/ux/00-workflow.md` §14): единый
`_module_nav.html` вместо трёх реализаций вторичной навигации, сокращение
брейкпоинтов, замер визуального диффа на **немигрированных** страницах —
фундамент не имеет права менять то, что ещё не мигрировали.

**Если подпись не получена** — правки идут в те же семь экранов, набор
оснований не расширяется; замечания записываются в §7 того же файла.

**Критерии выхода P3 — выполнены:**

1. Каждая проблема тяжести ≥ M имеет ровно одно решение.
2. Контраст каждой объявленной пары посчитан **числом**; пять провалов
   названы, для трёх подобраны значения, для двух принято удаление.
3. Чекер написан, **фиксирует известный базовый уровень** (40 таблиц не на
   `vs-table`, 213 цветов мимо токенов, 37 брейкпоинтов вне шкалы, 4 дубля,
   2249 строк inline-CSS, 142 глифа) и разрешает ему только уменьшаться.
4. **Отрицательный контроль пройден:** 12 самотестов парами «чистый образец
   даёт ноль, грязный — ровно свои нарушения»; на живом дереве три
   дописанных нарушения дали код выхода 1, откат — 0.
5. Решение по тёмной теме принято и заложено архитектурой, не палитрой.

**Открыто, не блокирует P4:** кто делает схемную часть справочника единиц
(DD-004) — трек UI миграций не берёт.

**Критерии выхода P1 — выполнены:**

1. `python tools/ux/inventory.py` дважды подряд даёт побайтово одинаковый JSON — проверено `cmp`.
2. Обход: 560 кадров, **ноль маршрутов с необъяснённой ошибкой рендера**; единственная ошибка `/drones/works/import/20/report` 404 объяснена — партии импорта с таким идентификатором нет ни в фикстурах, ни на боевой базе.
3. `a11y-baseline.json` содержит числа по серьёзности: 791 serious, 367 critical.
4. У каждой записи проблемного регистра есть артефакт-доказательство.
5. Отрицательные результаты записаны отдельно, чтобы закрытые гипотезы не выдвигались заново.

**Что уже изменило план по данным боевой базы** (`docs/ux/10-metrics/README.md`):

- **Порядок эталонных экранов изменён.** `/entry/save` даёт 1896 из 2284
  действий человека — 83 %. `daily_entry.html` становится первым canonical

- **Прогон на `lang=uz` обязателен**, не подмножество: узбекские подписи на
  19–47 % длиннее русских в тех же полях.
- **Контракт таблицы обязан объявить режимы по объёму**: от 394 817 строк
  (`fuel_transactions2`) до 3 (`work_orders`), плюс двенадцать всегда пустых
  таблиц.
- **Пустое состояние — основной сценарий** для двенадцати экранов, а не
  крайний случай.

**Ответы владельца, полученные 2026-08-09** (оба прежних вопроса закрыты):

- Спад активности операторов — переход на программу-конкурент `agrowork.uz`.
  Сигналом о качестве интерфейса не является и в проблемный регистр не идёт.
  Доля 83 % измерена на июне-июле и описывает, **чем является работа**, а не
  сколько её сейчас, поэтому приоритет `daily_entry` сохраняется.
- Дроны и наряды — пробел журналирования, проверено в коде
  (`docs/ux/10-metrics/README.md`, M2).

**Мобильные устройства: сейчас не используются, использование
предполагается.** Поэтому 20 измеренных горизонтальных переполнений
(15 на 390 px, 5 на 1024 px) регистрируются как «сломано к моменту, когда
понадобится», а не как действующий отказ: приоритет ниже плотности таблиц
сегодня, но со сроком, а не «когда-нибудь».

**Открытое решение на гейт P3 — одна поверхность или две.** От него зависит,
входит ли ретрофит адаптивности существующих страниц в фундамент:

- *Одна поверхность* — веб доводится до полной адаптивности, Mini App
  показывает те же страницы. Тогда починка `/ref/equipment` на 390 px
  (документ 1170 px в окне 390 px) — фундаментальная работа.
- *Две поверхности* — веб остаётся desktop-first, Mini App получает
  собственные экраны под задачу. Тогда справочник техники на 390 px чинить
  незачем: туда с телефона не пойдут ни при каком раскладе.

Дизайн-система общая в обоих случаях: токены, компоненты и правила плотности
переносятся. Различается только объём ретрофита существующих страниц.

**Staging:** площадка освобождена 2026-08-09, трек UI — следующий в очереди.
**Слот намеренно не занят**: staging по адресу `10.103.25.14:5051` недостижим
из облачной среды разработки (внутренний LAN, TCP-таймаут), поэтому держать
площадку сейчас означало бы блокировать соседние треки без возможности ею
пользоваться. Слот берётся на P7, когда появится что валидировать; обход
staging к тому моменту запускается Claude Code CLI с сервера предприятия.

**Release gate:** `docs/RELEASE_GATE.md` не пуст (`DRONE-WORKS-UPLOAD-001`) —
прод-деплой закрыт для всего проекта, не только для этого трека.

## 3a. Как поднять среду в новой сессии

Ничего из этого не хранится в репозитории и обнуляется вместе с контейнером.
Порядок ровно такой; шаги 2 и 3 нужны только если предстоит съёмка.

```
# 1. Зависимости приложения (контейнер, не сервер).
pip install -q -r requirements.txt

# 2. Node-инструменты. Браузеры УЖЕ установлены в /opt/pw-browsers --
#    playwright install не запускать, он скачает вторую копию.
cd tools/ux && PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1 npm install --silent && cd ../..

# 3. Эфемерный экземпляр: настоящее приложение на одноразовой базе.
#    Поднимать ОТЦЕПЛЕННЫМ, иначе он умрёт вместе с командой.
nohup setsid python3 tools/ux/serve_ephemeral.py --port 5099 --rows 22 \
      > /tmp/serve.log 2>&1 < /dev/null & disown
#    Готовность: curl даёт 200 на /login примерно через 20 секунд.

# 4. Съёмка (полная матрица ~50 минут, один вьюпорт ~13).
PLAYWRIGHT_BROWSERS_PATH=/opt/pw-browsers node tools/ux/shoot.mjs
PLAYWRIGHT_BROWSERS_PATH=/opt/pw-browsers node tools/ux/shoot.mjs --viewports desktop --limit 8
```

Учётные записи эфемерного экземпляра, пароль у всех `ux-audit-local`:
`ux_admin` (ru), `ux_admin_uz` (uz), `ux_operator`, `ux_viewer`, `ux_mechanic`.

**Язык интерфейса берётся из учётной записи, а не из адреса.** Прогон на
узбекском делается `--role ux_admin_uz`; флаг `--lang` — только метка
каталога. Параметр в адресе приложение игнорирует, и прогон молча снимется
на русском.

**Проверки перед любым отчётом о готовности:**

```
python -m compileall -q .
python tools/check_templates.py
python tools/test_check_templates.py
python tools/check_design_system.py
python tools/test_check_design_system.py
python -m unittest discover -s tests      # 481 тест, около 70 секунд
python tools/ux/inventory.py              # числа в документах регенерируются
```

## 5. Правила трека

- Изменяются только файлы из `AFFECTED FILES` спецификации задачи.
  `git add -A` и `git add .` запрещены — только поимённо.
- Откат — `git revert` в обратном порядке. `git reset --hard` запрещён.
- Мерж PR — merge commit, не squash.
- Любой скрипт трека — **читатель**: не импортирует `app` (иначе
  `db.create_all()` на импорте). Приложение поднимается только через
  `tests/harness.py` на одноразовой базе.
- `requirements.txt` не меняется. Node-инструменты живут в `tools/ux/` со своим
  `package.json`, `node_modules/` в `.gitignore`.
- `playwright install` не запускать: браузеры предустановлены.
- Ни одного действия на production. Read-only обход — только по белому списку
  URL и только если staging не даёт материала.
- Переход к следующей фазе — только по критериям выхода из
  `docs/ux/00-workflow.md` §14. «Выглядит нормально» критерием не является.
