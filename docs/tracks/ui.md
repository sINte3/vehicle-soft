# Трек: UI/UX

Точка входа трека. Новая сессия читает **этот файл первым**, дальше — по
ссылкам. Полная процедура работы — `docs/ux/00-workflow.md`.

## 1. Цель и границы трека

Довести интерфейс до состояния, в котором одна и та же функция выглядит и
ведёт себя одинаково во всех модулях, и **закрыть путь обхода дизайн-системы**,
которым эта одинаковость разрушалась до сих пор. Функциональность не меняется:
трек не трогает бизнес-правила, схему БД и деловое содержание выгрузок.

**Не входит:** новые экраны и новые отчёты; изменение смысла колонок Excel/PDF;
`_perform_fuel_sync`; миграции (у трека их быть не должно — необходимость
миграции означает выход за границы); проектирование Telegram Mini App
(заморожено по CLAUDE.md); визуализация данных (её в продукте нет — заводить
или нет, отдельное решение владельца, см. `docs/ux/00-workflow.md` §14 P3).

**Тёмная тема — больше не «вне объёма», решение перенесено на гейт P3.**
Владелец сообщил 2026-08-09, что планирует Telegram Mini App со всей
функциональностью по ролям и правам. Mini App — это webview: он рендерит тот
же HTML и CSS, а по соглашению Telegram наследует тему пользователя, включая
тёмную. Сейчас 90 токенов — плоские hex в одном `:root`. Заложить два набора
в архитектуру токенов дёшево; ретрофитить тёмную тему в уже разошедшиеся
значения плюс 213 хардкод-цветов — работа другого порядка. Проектирование
самого Mini App в трек по-прежнему не входит.

**Общие файлы.** Трек по определению правит `templates/base_next.html` и
`static/css/design-system.css` — оба в списке общих. Это объявление соседним
трекам (Дроны, АЗС, Запчасти, GPS): планируйте правки этих двух файлов с
оглядкой на трек UI, конфликты слияния наиболее вероятны здесь.

### P6 — миграция модулей, идёт

По одному PR на модуль, в порядке из `00-workflow.md` §14: `ref_*`/admin
(мелкие, обкатка) → `wialon` → `work_orders` → `spare_parts` → `fuel`
(крупнейший, 21 шаблон) → добивка остатков. Дроны уже на системе — им нужна
только сверка.

Формулировка задачи миграции — **«привести модуль к контрактам §6
спецификации»**, а не «улучшить дизайн модуля». Это половина защиты от
бесконтрольной полировки; вторая половина — чекер.

Критерии выхода на каждый PR (§14):

1. `check_design_system.py` по модулю чист;
2. одноразовых `*-table`-классов в модуле — 0;
3. inline-CSS модуля сокращён до порога из спецификации задачи;
4. до/после на 4 вьюпортах приложены, дифф просмотрен;
5. тесты модуля зелёные; смысл выгрузок Excel/PDF не изменён;
6. axe по модулю: 0 serious/critical — **на десктопе и на 390 px**.

### Открытые пункты, найденные при миграции модулей

Ни один не относится к вёрстке; каждый требует слова владельца, поэтому
записан, а не решён «по смыслу».

1. **`audit_logs.html` целиком по-русски.** Устав требует двуязычия. В словаре
   нет узбекских формулировок для «Фильтр», «С даты», «По дату», «Модуль»,
   «Объект», «Описание», «Записей нет». Придумывать термин и вводить его в
   продукт — не работа миграции вёрстки.
2. **Три ключа `t()` отсутствуют в словаре** и потому печатаются как есть, на
   обоих языках: `'Временный пароль (при вводе потребует смену)'` в
   `admin_users`, `' выберите организацию '` и `' выберите категорию '` в
   `ref_equipment`. Дефект пришёл из прежней редакции и перенесён дословно.
3. **`/ref/equipment` — 336 строк при пороге `is-static` ~200.** Разбиения на
   страницы сегодня нет вовсе; ввести его — значит поменять то, как оператор
   ищет по списку. Порог в DD-028 сам помечен непроверенным предположением,
   измерение — P7.
4. **`t('Фаол')` переведено как «Активные»** — множественное число в колонке,
   где значение относится к одному пользователю. Строка словаря, а не вёрстки.
5. **`templates/wialon_mapping.html` недостижим.** `render_template` его не
   вызывает ниоткуда, а его форма отправляется на `url_for('wialon_save')` —
   эндпойнта с таким именем в приложении нет вовсе, и попытка отрисовать
   шаблон падает `BuildError`. Экран ручного разбора импорта перестал
   существовать раньше файла. Удалить шаблон или восстановить тракт — решение
   владельца; пока оно не принято, шапка файла говорит о его состоянии прямо.
6. **Русской стороны у подписей Виалона нет.** В `wialon_mapping.html` было
   26 пар вида `'Виалон — Маппинг' if is_ru else 'Wialon — Mapping'` — один
   язык, узбекский, в двух алфавитах. Латиница уставом запрещена и убрана;
   следствие в том, что русский пользователь этих экранов видит узбекский.
   `wialon_report.html` целиком узбекский изначально.

**Открытое решение на гейт P3 — одна поверхность или две.** От него зависит,
входит ли ретрофит адаптивности существующих страниц в фундамент:

  собственные экраны под задачу. Тогда справочник техники на 390 px чинить
  незачем: туда с телефона не пойдут ни при каком раскладе.

Дизайн-система общая в обоих случаях: токены, компоненты и правила плотности
переносятся. Различается только объём ретрофита существующих страниц.

## 3a. Как поднять среду в новой сессии

Ничего из этого не хранится в репозитории и обнуляется вместе с контейнером.
Порядок ровно такой; шаги 2 и 3 нужны только если предстоит съёмка.

```
# 1. Зависимости приложения (контейнер, не сервер).
pip install -q -r requirements.txt

# 2. Node-инструменты. Браузеры УЖЕ установлены в /opt/pw-browsers --
#    playwright install не запускать, он скачает вторую копию.
cd tools/ux && PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1 npm install --silent && cd ../..

# 3. Эфемерный экземпляр: настоящее приложение на одноразовой базе.
#    Поднимать ОТЦЕПЛЕННЫМ, иначе он умрёт вместе с командой.
```

каталога. Параметр в адресе приложение игнорирует, и прогон молча снимется
на русском.

## 5. Правила трека

- Изменяются только файлы из `AFFECTED FILES` спецификации задачи.
  `git add -A` и `git add .` запрещены — только поимённо.
- Откат — `git revert` в обратном порядке. `git reset --hard` запрещён.
- Мерж PR — merge commit, не squash.
- Любой скрипт трека — **читатель**: не импортирует `app` (иначе
  `db.create_all()` на импорте). Приложение поднимается только через
  `tests/harness.py` на одноразовой базе.
- `requirements.txt` не меняется. Node-инструменты живут в `tools/ux/` со своим
  `package.json`, `node_modules/` в `.gitignore`.
- `playwright install` не запускать: браузеры предустановлены.
- Ни одного действия на production. Read-only обход — только по белому списку
  URL и только если staging не даёт материала.
- Переход к следующей фазе — только по критериям выхода из
  `docs/ux/00-workflow.md` §14. «Выглядит нормально» критерием не является.
