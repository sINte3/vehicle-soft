# Трек: UI/UX

Точка входа трека. Новая сессия читает **этот файл первым**, дальше — по
ссылкам. Полная процедура работы — `docs/ux/00-workflow.md`.

## 1. Цель и границы трека

Довести интерфейс до состояния, в котором одна и та же функция выглядит и
ведёт себя одинаково во всех модулях, и **закрыть путь обхода дизайн-системы**,
которым эта одинаковость разрушалась до сих пор. Функциональность не меняется:
трек не трогает бизнес-правила, схему БД и деловое содержание выгрузок.

**Не входит:** новые экраны и новые отчёты; изменение смысла колонок Excel/PDF;
`_perform_fuel_sync`; миграции (у трека их быть не должно — необходимость
миграции означает выход за границы); тёмная тема; Telegram Mini App;
визуализация данных (её в продукте нет — заводить или нет, отдельное решение
владельца, см. `docs/ux/00-workflow.md` §14 P3).

**Общие файлы.** Трек по определению правит `templates/base_next.html` и
`static/css/design-system.css` — оба в списке общих. Это объявление соседним
трекам (Дроны, АЗС, Запчасти, GPS): планируйте правки этих двух файлов с
оглядкой на трек UI, конфликты слияния наиболее вероятны здесь.

## 2. Ключевые факты, измеренные на коммите `493fd72`

Всё прочитано в репозитории командами, не взято из представлений о продукте.
Полная таблица с методом получения — `docs/ux/00-workflow.md` §0.

- **Дизайн-система существует и доказана.** `static/css/design-system.css` —
  1365 строк, 90 токенов, 16 секций. Модуль дронов (22 шаблона, самый новый) —
  100 % на `vs-*`, ноль легаси-переменных. Задача не «создать систему», а
  «замкнуть»: покрытие + запрет обхода.
- **CSS вне системы больше, чем внутри:** 2292 строки inline-`<style>` в 38
  шаблонах против 1365 строк дизайн-системы. Плюс 2836 строк inline-JS в 37
  шаблонах при одном внешнем JS-файле на 7 КБ.
- **Покрытие системы:** из 86 шаблонов 40 на `vs-*`, 18 смешанных, 22 только на
  легаси-переменных, 5 без признаков системы, 1 (`report.html`) на отдельном
  языке `--ux-*`.
- **Таблиц 104.** На `vs-table` — 64, без класса — 18, и **15+ одноразовых
  классов, названных по кодам задач** (`fuel002a-table`,
  `fuel002d-report-table`, `fuel002h-dashboard-table`, `station-totals-table`,
  `workload-table`…). Это главный симптом: инкремент делает свой CSS вместо
  общего компонента, потому что ничто этого не запрещает.
- **Три реализации вторичной навигации:** `_spare_nav.html` 110 строк,
  `fuel/_fuel_nav.html` 136, `drones/_drones_nav.html` 31.
- **Иконки:** 53 инлайновых `<svg>` в 6 шаблонах (18 из них в `base_next.html`)
  против **228 вхождений эмодзи, 43 различных глифа** в контентных страницах.
- **Классического «AI-slop» здесь нет:** градиентов 5 на весь проект, базовый
  шрифт 13 px, потолок шкалы 23 px, внешних шрифтов и CDN ноль. Реальные
  кандидаты другие: эмодзи вместо иконок, цветные тени-свечения
  (`--vs-shadow-primary`), 6 ступеней радиуса, 8 брейкпоинтов без шкалы.
- **Визуализации данных нет вовсе:** 0 `<canvas>`, ни одной чарт-библиотеки.
- `tests/harness.py` собирает **настоящее приложение** на одноразовой SQLite во
  временном каталоге → визуальный аудит возможен **без staging и production**.
- В истории есть дефекты «GET с побочным эффектом»
  (`RELEASE_AUDIT_GET_SIDE_EFFECT_001/002/003`: экспорт Wialon, выгрузка
  workload, logout по GET). Следствие: обход production краулером по ссылкам
  **опасен**; только белый список URL без переходов.
- Предыдущий аудит `docs/UI_HOMOGENEITY_AUDIT.md` (TASK-UI-AUDIT-001,
  2026-07-06) охватывал 42 шаблона; сейчас их 86. Фаза 11 выполнена, фазы 12–16
  предложены и не подтверждены. Модуль дронов возник после того аудита.
- Указатель CLAUDE.md на `docs/AGENT_STATE.md` и `docs/TASKS.md` устарел: файлы
  в `docs/archive/`.

## 5. Правила трека

- Изменяются только файлы из `AFFECTED FILES` спецификации задачи.
  `git add -A` и `git add .` запрещены — только поимённо.
- Откат — `git revert` в обратном порядке. `git reset --hard` запрещён.
- Мерж PR — merge commit, не squash.
- Любой скрипт трека — **читатель**: не импортирует `app` (иначе
  `db.create_all()` на импорте). Приложение поднимается только через
  `tests/harness.py` на одноразовой базе.
- `requirements.txt` не меняется. Node-инструменты живут в `tools/ux/` со своим
  `package.json`, `node_modules/` в `.gitignore`.
- `playwright install` не запускать: браузеры предустановлены.
- Ни одного действия на production. Read-only обход — только по белому списку
  URL и только если staging не даёт материала.
- Переход к следующей фазе — только по критериям выхода из
  `docs/ux/00-workflow.md` §14. «Выглядит нормально» критерием не является.
