# Трек: GPS план-факт

> Handoff по формату запроса от 2026-07-29. Для `docs/tracks/gps-plan-fakt.md`.

## 1. Цель и границы трека

Измерять факт выполнения работ по треку GPS: обработанную площадь в гектарах за произвольный интервал по паре
«техника + контур», чтобы закрывать наряд и выставлять счёт контрагенту защитимой цифрой. Стратегическая рамка
— нишу против agro-work.uz держит не GPS, а связка гектара с фактической выдачей топлива Topaz.

**Не входит:** агрономия (культуры, севооборот, нормы), планирование работ, ввод нарядов как таковой, рейсовые
перевозки (отдельная задача, только эскиз), переписывание справочника контуров в Wialon, любые записи в
Wialon.

## 2. Ключевые архитектурные факты

Источник — реальные ответы Wialon Remote API и расчёты по ним, не отчёты агентов.

- Wialon **Local**, `https://web.gpstrack.uz` → **195.158.11.71**, публичный адрес, сервер интегратора, **не в
  сети кластера**. Внутренний DNS `10.103.25.3` отдаёт тот же публичный IP. Версия ~2504 — со слов владельца,
  лично не проверял.
- Пользователь «Бухоро агрокластер» `id=284`, родительский аккаунт `169`.
- Ресурсы: `285` — **17 812 геозон**; `170` «Дилер 1» — **0 геозон**. Контуры наши, зависимости от дилера в
  них нет.
- Объектов видно **482**; наш реестр техники ~340, разница — легковые, погрузчики, экскаваторы, комбайны.
- **IMEI (`uid`) базовым флагом не отдаётся.** Постоянный ключ сопоставления — `wialon_id`. Переименования в
  Wialon его не ломают.
- Код региона присутствует только в **189 именах из 482**; 6 номеров указывают на несколько объектов; «New
  Holland 80 605 EA» существует тремя объектами (`10077`, `10011`, `2982`) — история замены трекеров.
  Автоподбор по номеру — предложение, а не источник истины.
- **Контур по имени определять нельзя.** «1508 Нурхон Бобохон» — две разные зоны (`3207` 4,32 га и `3208` 8,97
  га); у одного контрагента ~150 зон, повторов номера минимум четыре. Контур определяется **по треку**: какие
  полигоны содержат точки в рабочем режиме.
- Датчики на 16 проверенных тракторах: топливо `[LLS1]+[LLS2]` (`io_201`, `io_203`), зажигание `io_239` как
  моточасы, одометр `io_199`. **ВОМ нет.** У 10 единиц есть «Прицеп» на `io_78` — это вход iButton; стоят ли
  считыватели физически, не проверено.
- Трекеры Teltonika FMB125/FMB920: в движении 30 с / 100 м / поворот 10° / скачок 10 км/ч, отправка 60 с,
  стоянка 30 мин. Фактическая плотность в работе **14–28 с на точку** — триггер по повороту сгущает точки на
  разворотах, то есть на границе полигона.
- Метод расчёта площади (зафиксирован, проверен): точки в окне **1–15 км/ч** и внутри контура → сгущение пути
  каждые **5 м** → альфа-форма по Делоне с **альфа = 10 м** → объединение → обрезка по контуру → площадь в
  **UTM 41N** (EPSG:32641). Реализация: `shapely`, `scipy.spatial.Delaunay`, `pyproj`.
- **Ширина захвата агрегата не используется нигде.** Шаг между проходами измеряется из самого трека: 5–9 м у
  культиватора, 13–14 м у опрыскивателя.
- Результат на проверочном наборе 27.07 (17 работ, метод объявлен письменно до получения данных): медиана
  расхождения с ручным замером **3,3%**, среднее −4,0%; сумма 51,71 га расчёта против 53,09 га ручных.
- Проверка проекции: площадь контура 2714 из геометрии Wialon **42,30 га** против паспортных 42,16 га
  (+0,33%), цифры получены разными путями.
- Правило начисления при совместной работе — **сумма по единицам техники** (2714: 6,792 + 6,933 га за день),
  со страховкой: считать рядом объединение полигонов и помечать пересечение, если сумма его превысила.

**Чего экран пока не делает** (не дефекты, а зависимости):

  только справочник наполнится: расчёт уже кладёт `contour_id`.
- **Интервал — ровно сутки.** Агрегаты суточные; произвольный интервал
  потребует складывать участки за несколько дней, а это уже вопрос о том,
  как не посчитать одну и ту же землю дважды.

**GPS-4 сделан 19.08:** `tools/gps_mirror_contours.py` тянет геозоны ресурса
285 и кладёт их в `field_contours` (`source='wialon'`, `external_id` — id
зоны). Скрипт **ничего не удаляет и не гасит**: контур, пропавший из Wialon,
остаётся как был — на него могут ссылаться выставленные счета (решение G8).
Площадь контура он тоже не считает: её умеет метод, а вторая реализация дала
бы два числа для одной вещи. Дубли имён — в отдельный CSV: справочник содержит
их по конструкции, и это не ошибка импорта.

**На сервере зеркало ещё не запускалось.** Как только запустится, у участков
на экране GPS-3 появятся имена полей: расчёт уже кладёт `contour_id`, ему не
хватало только наполненного справочника.

**GPS-5 сделан 19.08.** Экран `/gps/orders`: наряд, закрытый объём, факт по
треку, расхождение и светофор по допускам В-2. Сверяется с тем объёмом, за
который выставят счёт (`actual_quantity`, при его отсутствии — план).

Три решения, которые стоит помнить:

- **Считаются только гектары.** Моточасы и километры GPS-2 не публикует:
  `io_239` и `io_199` коллектор не собирает, а `track_km` в агрегате есть, но
  его точность не проверена (В-6, пилот на 3–5 машинах). Для прочих единиц
  вердикт — `no_data` с причиной, а не молчаливый ноль.
- **Предрегистрированное правило «≥ 1,3 га ИЛИ ≥ 25 мин» в счёт не берётся
  вовсе.** Участок, названный человеком проездом, вычитается; участок без
  ответа входит (он прошёл подтверждённый порог 0,3 га), и рядом с цифрой
  стоит, сколько таких участков и гектаров. Считать деньги по непринятому
  правилу значило бы ввести его в обход собственного протокола приёмки.
- **Неоднозначная связь не угадывается.** Машина, сопоставленная с несколькими
  объектами Wialon (у одной их три — история замены трекеров), даёт `no_data`:
  сложить объекты значит посчитать работу дважды, выбрать один — угадать.

**GPS-6 сделан 19.08.** Очередь исключений оказалась не отдельным экраном, а
недостающим действием: фильтр «требует внимания» уже был, не было разбора.
Теперь на строке вне допуска стоят две кнопки — «подтвердить» и «оспорить» с
объяснением, — и каждое нажатие пишет строку в `gps_verdicts`.

Три свойства журнала, которые важнее экрана:

- **Только добавление.** Второй разбор того же наряда добавляет строку, а не
  заменяет прежнюю. История и есть тот набор, по которому раз в сезон
  пересматриваются допуски (§3.2); замена вместо добавления уничтожала бы его
  молча, а экран при этом выглядел бы правильно.
- **Числа лежат снимком.** Пересчёт суток не переписывает то, что было перед
  глазами человека: журнал, где написано «подтверждено», а число рядом молча
  изменилось, хуже отсутствия журнала.
- **Разбор не меняет ни одного числа.** Ни агрегата, ни полигонов, ни объёма
  наряда. Дать разбору править факт значило бы превратить измерение в мнение.

**GPS-7 сделан 19.08.** `gps_sync_log` заполняется коллектором и показывается
на `/gps/sync`. До него «коллектор отработал и ничего нового не нашёл» было
неотличимо от «коллектор не запускался»: точки лежат вне `transport.db`, и
посмотреть на них из приложения нельзя вовсе.

- **Тождество, по образцу инварианта `drone_sync_logs`:** `messages_seen =
  points_written + points_duplicate + points_no_position`. Прежний сборщик
  дронов всегда писал `written == seen`, и по такому журналу нельзя было
  ответить, приехало ли что-нибудь новое. Несходящееся тождество экран
  показывает первым, а не прячет в столбце.
- **Журнал никогда не останавливает сбор.** Нет базы, нет таблицы, база не
  открывается — прогон заканчивается нормально, точки лежат, причина
  печатается. Точки важнее записи о точках.
- **Прерванный прогон оставляет о себе запись** со статусом `error`: иначе
  утром он неотличим от прогона, которого не было.

**GPS-8 сделан 19.08.** `docs/GPS_ROLLOUT_RUNBOOK.md` — весь порядок выката в
одном месте: три миграции по одной, первый прогон коллектора, проверка приёма
глазами, суточный расчёт, зеркало контуров, расписание Task Scheduler,
ретенция, таблица «симптом → что это значит → что делать» и откат. Числа в нём
не пересказаны по памяти, а сверены с кодом: строки вывода миграций, счётчики
колонок и индексов, подписи разделов.

`tools/gps_retention.py` — удаление помесячных файлов старше 90 дней. **Сухой
прогон по умолчанию, `--apply` человек пишет руками**, расписания у него нет и
быть не должно: устав запрещает удалять продовые данные автоматически.

Написание ранбука вскрыло дефект интерфейса: чтобы посчитать «вчера» в
`.bat`-обёртке, нужен был `for /f` вокруг PowerShell со вложенными кавычками —
конструкция, где кавычка съедает половину команды и задача молча не
запускается. Причина убрана: `gps.daily` без `--date` сам берёт вчерашние сутки
по местному времени.

**GPS-9 сделан 19.08.** `gps/tests/test_end_to_end.py` — единственная проверка,
которая видит **швы** между слоями. Настоящий трек 3464 за 27.07 идёт через
консервированный Wialon, коллектор, watermark, помесячный файл, суточный
расчёт и миграцию, и на том конце обязан дать записанные 8,772 га. Пять мутаций
на швах (перестановка долготы и широты, чтение половины суток, запись не в свой
месяц, потеря спутников, невызванный `unload`) роняют её, правка без изменения
поведения — нет.

Побочно проверено и то, что журнал приёма **не роняет прогон**: в первой
редакции теста третья миграция не применялась, и журнал честно промолчал, а
цепочка досчитала до конца.

**Что делать первым делом:** километры вторым измерением в сверку — `track_km`
в агрегате уже есть, допуск по км владельцем дан, не хватает только ответа по
В-6 (3–5 машин с исправным одометром для пилота). Пока ответа нет, брать
`io_199` в вердикт нельзя: точность одометра не проверена ни на одной машине.
**Всё, что можно построить на измерениях, не спрашивая владельца, построено;
дальше упирается в четыре ответа — В-6, В-23, судьба пропавшего контура и

**Чего ждём от владельца:** применения миграции и первого ночного прогона
коллектора на сервере, ответа интегратора по лимитам,

## 6. Грабли этого трека

- **Пустой ответ `core/search_items` — не отказ в правах.** Поиск юнитов по списку id вернул 0 объектов из-за
  неверной спецификации; было принято за отсутствие прав. Работает `core/search_item` по одному объекту.
- **Полигоны и точки должны быть в одной системе координат.** Полигон в градусах против точек в UTM даёт
  `contains() == False` на всех точках и тихий ноль.
- **Разрывы трека нельзя считать по всем сообщениям подряд:** на стоянке трекер пишет раз в 30 минут, и каждый
  простой попадает в «разрывы». Считать только между сообщениями в движении.
- **Относительный параметр вогнутой оболочки (`ratio` в shapely) не переносится между полями** — он
  масштабируется под размер облака точек. Нужен параметр в метрах.
- **Шаг точек вдоль прохода (35–55 м) больше шага между проходами (5–14 м).** Без сгущения пути альфа-параметр
  хрупкий: сшивает проходы только ценой перекрытия настоящих пропусков.
- Массивные формулы вида `MEDIAN(ABS(range))` в xlsx дают `#VALUE!` при пересчёте — считать в Python и писать
  литералом.
- Округление площадей в ручном учёте непостоянное: заявлена сетка 0,5 га, реально встречается 0,1 га, а случай
  7,57 → 8,0 выходит за обе. Ручные цифры годятся для оценки смещения, но не для проверки отдельного случая —
  нужны сырые.
