# Трек АЗС — финальный handoff

## 1. Цель и границы трека

Модуль ведёт учёт дизтоплива холдинга: остатки по складам, приходы, выдачи через ТРК
из Topaz, ручной расход, забалансовый резерв, отчёты. Его смысл — быть источником
правды о том, сколько топлива было, ушло и осталось, с точностью, которую можно
предъявить организации в споре.

**Не входит:** ГСМ кроме ДТ (цены и суммы в модуле не используются), учёт по
единицам техники и нормы расхода, наряды, Wialon. Модуль отвечает за склад и карту,
а не за машину.

## 2. Ключевые архитектурные факты

Всё ниже прочитано в исходнике `fuel_routes.py` и в схеме Firebird Topaz.

1. Формула остатка: `начальный + приход − выдачи Topaz − стороннее − передано в
   резерв + получено из резерва − ручной расход`. Ни один инкремент её не менял.
2. `_fuel_opening_for(...)` — **единственный** источник остатка на начало периода;
   его вызывают и балансовый отчёт, и карточка склада. Верхняя граница окна расхода
   в нём — явная полночь `datetime.combine(start_date, datetime.min.time())`, а не
   пользовательское `start_dt`. Если это сломать, время в фильтре утащит операции
   первого дня в остаток на начало.
3. `_fuel_balance_map` (от строки 681) учитывает ручной расход, стороннее топливо и
   резерв — поэтому цифры дашборда совпадают с балансовым отчётом.
4. Карта `30` (ПЕРЕЛИВ) отбрасывается **на приёме**, в `_perform_fuel_sync`, до
   разрешения АЗС и до дедупликации. В `fuel_transactions2` она не попадает никогда.
   Рядом с этим `continue` теперь пишется строка в `fuel_counter_mismatches`
   (`INSERT OR IGNORE` по уникальному `(topaz_col_id, topaz_txn_id)`, обёрнуто в
   `try` — на базе без миграции синхронизация не падает).
5. Записи расхождений копятся **только вперёд** от применения миграции плюс
   трёхдневное окно перечитки агента. Историю восстановить нечем.
6. Имена карт: `_resolve_card_names` сопоставляет `card_number` с `alias_value`
   типов `topaz_card_id` и `rfid` в `fuel_card_aliases`. Один вызов на страницу.
7. Видимость складов: `fuel_target_warehouse_ids` / `fuel_warehouse_query_for_ui`,
   флаги `show_in_ui` и параметр `show_legacy`. Рабочих 23, всего 30 — числа
   вычисляются, в шаблонах их больше нет.
8. `module_required` навешивает `@login_required` на собственную обёртку, то есть
   **заменяет** его, а не складывается с ним. `has_module_access` для админа всегда
   `True`. Админские страницы: `/fuel/initial-balance`, `/fuel/manual-expenses`,
   `/fuel/reserve-transfers`, `/fuel/stations`.
9. Период: `_fuel_parse_period`, верхняя граница исключающая. Приходы, ручной расход
   и начальные остатки хранятся **без времени** — они фильтруются по дате целиком.
10. В книге карточки склада раздел записан в колонку A (`Склад` / `Резерв` /
    `Стороннее`), подытоги и общий итог считаются `SUMIFS` по этой метке. Общий итог
    складывает только балансовые разделы.
11. Отчёты по картам и по АЗС считают **все** литры через колонку, включая
    стороннее; балансовый отчёт — только своё. Разница между ними всегда равна
    сумме стороннего топлива.
12. Topaz Firebird: статус карты **не** в `dcCards.Enabled` (там 1 у всех 4891), а в
    `dcLimitRestrictions.LimitTypeID` при `AmountID = 2` (кошелёк ДТ): `4` —
    «Запрещён» (525 карт), `7` — «Календарный день» (4373).
13. Остаток карты = `SUM(rgAmountRests."Rest")` по `CardID`. `Rest` — это движение,
    а не остаток; `rgChargeCardRests` пуста. `Odometr` и `EngineHours` заполнены в
    нуле строк из 471 518 — моточасы из Topaz не придут.
14. В `dcCards` есть псевдокарта `CardID = 0` («< Не выбран >») с множеством строк
    ограничений. Любой запрос по картам обязан её исключать.
15. Модуль резервуаров Topaz (`dcTanks` 20 строк, `dcSnapshotsTanks` 101 464) —
    **проверенный тупик**: холдинг им не пользуется, уровнемеров нет. Источником
    данных для фазы 3 не является, не переоткрывать.

## 6. Грабли этого трека

- **`_fuel_opening_balance` был мёртвым и неполным** — не учитывал ручной расход,
  стороннее и резерв, но выглядел как готовый хелпер. Удалён коммитом `08ab1c2`.
  Если что-то похожее появится снова, карточка молча разойдётся с отчётом.
- **Прототип `fuel_ledger_002.py` считает остаток на начало без прокрутки** от даты
  начального остатка. Совпадает с программой только когда период начинается ровно в
  эту дату. Как образец формата — годится, как источник арифметики — нет.
- **Склады-дубли.** «Мирзачул ПТЗ» и «Вобкент ПТМ» существуют дважды. Искать склад
  по имени нельзя, только по id; в выпадающих списках id показывается специально.
- **Имена скачанных файлов ASCII.** Не судить о локализации выгрузки по имени
  файла — оно не переводится. Проверять содержимое книги.
- **`paperSize` по умолчанию Letter**, не A4. В новых выгрузках задан явно.
- **Отчёты по картам всегда больше балансового** ровно на стороннее топливо. Это не
  расхождение; на обоих отчётах стоит постоянное примечание.

## 7. Данные, которые надо собирать заранее

- **Тарировочные таблицы и инвентарь ёмкостей по всем складам.** Без них фаза 3 не
  начинается вообще: в базе нет ни одной ёмкости, а в Topaz данные не заполнены.
  Бланк на узбекском (кириллица) готов, **не разослан**. Просить фотографии
  таблиц, а не переписанные от руки цифры. Недели календарного времени.
- **Нормы расхода на единицу техники** — для `FUEL-NORMS-001`. Моточасы из Topaz не
  придут, источник только Wialon. Норму нужно на каждую из ~340 единиц.
- **Решение по дублям складов** (`AZS-ORG-REFACTOR`): какой из двух одноимённых
  рабочий, какой архивный. Это решение человека по данным, кодом не выводится.
- **Десять карт с префиксом `DUB_name` в Topaz** — незавершённые замены по процедуре
  владельца. Чистятся в Topaz-Office руками, иначе так и лезут во все отчёты.
