# Сентябрь-2025: разбор до истины

`DRONE-SEPT2025-RECON-001`. Первый месяц помесячной кампании
(`docs/DRONES_HANDOFF_20260815.md`, §9). Разобран на файлах владельца от
2026-08-17: шесть книг диспетчеров, выгрузка вылетов, отчёт по работам и
ручная сверка.

Воспроизводится одной командой (только чтение, база не открывается):

```
python tools/drone_month_books_vs_flights.py --books-dir <каталог книг> --flights "Вылеты дронов Сентябрь.xlsx" --works-report "Отчет по работам Сентябрь 2025.xlsx" --month 2025-09 --assignments tools/drone_assignments_2025_09.json --out recon.xlsx --expect-books-ha 5617.03
```

Прогон печатает четыре строки, по которым видно, сошлось ли всё:

```
books   :  5541.03 ha in 408 rows (3 rows for other months)
flights :  5572.18 ha in 5661 flights
coverage: 0 flights not covered by the map
bridge  : books 5617.03 -> report 5140.93 (file says 5140.93, residual +0.00)
```

## 1. Три числа сентября и почему они разные

Владелец заметил, что числа расходятся между отчётами. Расхождение измерено
и объяснено полностью, до копейки:

| Источник | Гектары |
|---|---|
| Отчёт по работам (программа) | 5 140.93 |
| Книги диспетчеров (все строки) | **5 617.03** |
| Вылеты дронов (телеметрия DJI) | 5 572.18 |

Мост от книг к отчёту программы — четыре слагаемых, сумма сходится точно:

| Шаг | Гектары |
|---|---|
| Книги диспетчеров, все строки | 5 617.03 |
| − справки Холмуродова, датированные октябрём | −587.50 |
| − строка «Зухал Агро фх» 29.09 без номера, импортёр пропустил | −7.00 |
| + работы, которых нет в присланных листах (14 контрагентов) | +118.40 |
| **= отчёт по работам** | **5 140.93** |

Ручная сверка владельца даёт 5 617.00 — разбор книг сошёлся с его счётом
в пределах 0.03 га. Это и есть довод, что книги прочитаны верно.

**Книги против телеметрии: 5 617.03 против 5 572.18, разница 0.8 %.** На уровне
месяца стороны согласны. Расходилось не число месяца, а его распределение
по людям.

## 6. Чем проверено

| Утверждение | Чем |
|---|---|
| книги прочитаны верно | итог разбора 5 617.03 против 5 617.00 ручной сверки владельца |
| мост к отчёту программы верен | считает сам инструмент из обоих файлов: `bridge: books 5617.03 -> report 5140.93 (file says 5140.93, residual +0.00)`. Каждое слагаемое названо контрагентом на листе «Мост к отчёту»; отрицательный контроль — подменённый отчёт даёт ненулевую невязку |
| карта назначений полна | контроль покрытия: 0 вылетов из 5 661 вне правил; сумма по операторам 5 572.18 = итог выгрузки |
| проверки различают верное и неверное | четыре отрицательных контроля: без переноса справки Холмуродов даёт 36.7 % (вне порога); без правила — код 3 и 5 непокрытых вылетов; без алиаса — код 1 с именем и 884.50 га; **с текущей раскладкой базы — Хамроев 133.1 %, Хасанбой 79.9 %**, то есть ровно −102.5 и +107.35 га ручной сверки |
| порог доверия | 12 операторов из 13 в ±9 %; было 4 вне порога |
| формулы отчёта верны | **LibreOffice в контейнере пересчитать отказался** (`javaldx`), поэтому все 118 формул вычислены независимо по литералам: `Назначения!E20` = 5 661 вылет, `По операторам!E16` = 5 572.18, `C16` = 5 541.03, невязка моста = 0.00. Проверка нашла дефект: подпись «= Отчёт по работам (расчёт)» уходила в файл формулой и открылась бы ошибкой — исправлено, гвардия в `_put` и тест с отрицательным контролем. Книга несёт `fullCalcOnLoad`, поэтому Excel пересчитает при открытии |

**Не проверено:** ни одна цифра не сверена с production — сессия живёт в
контейнере, прода из неё не видно. Раскладка в БД **не изменена**: карта
лежит данными в `tools/drone_assignments_2025_09.json` и ждёт решения
владельца. Загрузка назначений и карты алиасов операторов — отдельный
инкремент.
