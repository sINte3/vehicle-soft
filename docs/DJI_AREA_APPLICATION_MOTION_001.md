# DJI-AREA-APPLICATION-MOTION-001 — плоский счётчик при применении без движения

Трек Дронов. Ветка `claude/dji-area-moving-application` от `4d921db` (то, на чём
стоит production). Миграций нет, схема не меняется, RAW и `billable_area_m2` не
трогаются, к DJI ничего не обращается.

**Итог в одной строке.** Строгое правило безопасно, но на реальной телеметрии
августа не закрывает ни одной записи из 25: при применении координаты
менялись хоть на сантиметры всегда. Всё остальное в очереди — вопрос допуска,
то есть решение владельца (§8).

## 1. Зачем

После исторического backfill 01.03–22.09.2026 крупнейшая группа ручной очереди —
`APPLICATION_WITH_FLAT_COUNTER`: 44 записи / 29,2688 га (41 после трёх решений
администратора). Резолвер отправлял туда ЛЮБУЮ запись, у которой проверенный
счётчик площади V4 плоский, а признак применения (флаг распыления или расход)
есть хоть в одном кадре. Причина — `resolver.py`: «либо площадь перенесена из
прошлой записи, либо это повторный проход по уже учтённой поверхности; отличить
их нечем, пока не посчитан независимый footprint».

Повторный проход — это сдвиг с распылением. Если при применении борт не сдвинулся
НИ НА ЧТО, прохода не было, и ноль счётчика — утверждение уже и о земле. Только
этот случай правило закрывает само. Любой наблюдённый сдвиг — 1 см, 0,3 м/с —
оставляет запись человеку: закрыть его можно только с допуском, а допуск —
эмпирический порог, которого нет.

## 2. Правило (версия `flat-counter-application-motion-2`)

Запись получает флаг `APPLICATION_PRESENT_WITHOUT_MOVING_WORK` (вместо
`APPLICATION_WITH_FLAT_COUNTER`) и попадает в проверенный подытог, если
одновременно:

1. окно V4 `GOOD`: личность файла подтверждена, кадров ≥ 2, концы в пределах
   1,01 с, шаг ≤ 1 с, счётчик не убывал — прежние замороженные гейты;
2. счётчик закодирован в первом и в последнем кадре, концы равны по битам
   float32 (прирост ровно 0), RAW > 0 — прежняя ветка
   `COUNTER_FLAT_RAW_OVERSTATED`;
3. применение наблюдалось (`application_frames > 0`, флаг ИЛИ расход);
4. **ни в одном кадре применения нет сдвига** (`v4.application_motion`):
   * ни одной закодированной ненулевой компоненты скорости vx/vy — без порога,
     0,1 м/с тоже сдвиг;
   * ни одного изменения координат на наблюдаемых шагах рядом с кадром
     применения (в кадр и из кадра, 0 < dt ≤ 1 с) — сравнение точное, без
     допуска в метрах;
5. **каждый кадр применения наблюдён**: обе компоненты скорости закодированы
   (нулём) либо рядом есть наблюдаемый шаг координат. Скорость, опущенная на
   проводе, нулём не считается;
6. путь по координатам рядом с применением **ровно ноль** — отдельное условие,
   не заменяющее п. 4;
7. оценка движения посчитана по тому же файлу (число кадров применения
   совпадает со сводкой) и той же версией правила.

Порог `MOVING_APPLICATION_MIN_SPEED_MPS` = 1,0 м/с в правило не входит: он
остаётся диагностикой исследования (колонки `moving_application_*` сводки).
Ширина полосы и структурное совпадение не участвуют. Учётный класс —
`PHANTOM_PROVEN` с причиной `APPLICATION_PRESENT_WITHOUT_MOVING_WORK`; принято 0,
исключено RAW, RAW не меняется; активность применения остаётся `PRESENT`.

**История.** Версия `-1` этой ветки считала стоянкой всё медленнее 1,0 м/с;
независимое ревью показало, что так реальный медленный проход (0,8 м/с,
2,3 м) получил бы ноль. `-1` в `main` не попала; `-2` — строгая.

## 3. Почему «нет данных о скорости» — не «стоял»

Август, 1410 файлов V4, 3 830 251 кадр, шаг кадра всегда 0,1 с:

| Факт | Число |
|---|---|
| Подсообщение скорости (поле 3) отсутствует | 0 кадров |
| vx и vy обе опущены (нуль protobuf) | 380 275 кадров |
| одна из двух опущена | 272 134 кадра |
| Кадры применения / из них флаг без расхода / расход без флага | 2 003 092 / 0 / 0 |
| Полная скорость > 2 м/с, а шаг координат ровно 0 (позиция повторилась) | 1 712 из 2 805 626 |

Опущенная компонента почти всегда значит ноль, но не всегда; повтор координаты
бывает и при настоящем движении. Поэтому неподвижность требует наблюдения, а
любой канал, увидевший сдвиг, её опровергает.

## 5. Версионирование: контракт выборочной версии

Правка, способная изменить результат уже записанной строки, обязана изменить
отпечаток этой строки. Контракт в `dji_area/__init__.py` разрешает два способа:

1. поднять `impl-N` — меняется отпечаток ВСЕХ строк;
2. выборочное правило из `resolver.SELECTIVE_RULES` — правило ДОБАВЛЯЕТ исход
   своим флагом, а без флага строка байт в байт та же. Его версия входит в
   отпечаток ровно тех строк, где флаг стоит (`pipeline.selective_rule_marks`),
   и никогда — в общую конфигурацию отпечатка. Правка смысла правила поднимает
   ЕГО версию; строка, где оно перестало срабатывать, возвращается к прежней
   (`reactivated`).

Это правило — способ 2. Способ 1 здесь стоил бы дорого: экран контроля, приёмка
и контрольная точка backfill читают строки по точному `AREA_ALGORITHM_VERSION`,
подъём скрыл бы историю до полного пересчёта, перевёл бы 202 окна `DONE` в
«algorithm changed» (повторный сбор DJI при следующем запуске backfill) и сделал
бы устаревшими решения администратора. `V4_PARSER_VERSION` тоже не поднят:
кэшированные сводки не меняются, оценка движения считается по телу V4 заново и
только для записей с плоским счётчиком и применением.

Держат контракт тесты `SelectiveVersionContract` (реестр, пустая метка у строки
без флага, метка меняет отпечаток, версия не входит в общую конфигурацию,
`impl-4` не сдвинут) и сквозные проверки того же файла (переписывается ровно
сработавшая запись, повтор — `unchanged`, откат кода — `reactivated`).

**Ранбуки.** Тройка «ветка, тег, отпечаток» в `DJI_AREA_PRODUCTION_RUNBOOK.md` и
`DJI_AREA_SIMPLIFY_001_RUNBOOK.md` переведена вместе с кодом, как 21.09:
`claude/dji-area-moving-application` / `dji-area-application-motion-001-rc1` /
`8f143183…`. Тег создаёт владелец на проверенном коммите ветки после ревью; до
этого любой блок останавливается на проверке тега, до первого действия. Для
проверки самого правила блоки не нужны.

## 6. Порядок на production (выполняет владелец)

**До деплоя** (закрывает строку гейта): код ветки из отдельного клона, база
production только читается (`mode=ro`, SHA файла до и после), служба может
работать. Тела V4 инструмент берёт из `instance\dji_sources` рядом с базой.

```powershell
git clone --branch claude/dji-area-moving-application https://github.com/sINte3/vehicle-soft.git C:\VehicleSoft_Motion_Rule
& "C:\Program Files\Python314\python.exe" C:\VehicleSoft_Motion_Rule\tools\dji_area_application_motion_eval.py --db C:\transport-report\instance\transport.db --out C:\VehicleSoft_Area_Motion_Eval_PreDeploy --flight-id 679813767 --flight-id 693319955 --flight-id 698068932 --flight-id 687610350
```

Ожидается `verdict : OK`, `would write N (without the rule firing: 0)`.
Команды `recalc_*.txt` из этого прогона указывают на клон и для записи НЕ
используются: писать production-базу можно только развёрнутым кодом.

**После деплоя** — те же шаги из корня развёрнутого репозитория; адресная запись
нужна, только если оценка покажет сработавшие записи.

```powershell
& "C:\Program Files\Python314\python.exe" tools\dji_area_application_motion_eval.py --db instance\transport.db --out C:\VehicleSoft_Area_Motion_Eval --flight-id 679813767 --flight-id 693319955 --flight-id 698068932 --flight-id 687610350
Invoke-Expression (Get-Content C:\VehicleSoft_Area_Motion_Eval\recalc_dry_run.txt -Raw)
```

Запись — только по решению владельца, со снятой копией базы:

```powershell
Copy-Item instance\transport.db instance\transport.db.backup_before_motion_rule
Invoke-Expression (Get-Content C:\VehicleSoft_Area_Motion_Eval\recalc_apply.txt -Raw)
Invoke-Expression (Get-Content C:\VehicleSoft_Area_Motion_Eval\recalc_apply.txt -Raw)
& "C:\Program Files\Python314\python.exe" tools\dji_area_idempotence_gate.py --summary C:\VehicleSoft_Area_Motion_Eval\recalc_apply.json
```

Если рядом с базой лежат `transport.db-wal` и `transport.db-shm`, они
копируются вместе с ней. `dji_area_backfill.py` для этого НЕ запускается.

Сентябрьская приёмка: её четыре `APPLICATION_WITH_FLAT_COUNTER` (`701661028`,
`702797709`, `703830892`, `703847599`) здесь проверить нечем — сентябрьских тел
V4 в среде разработки нет. Если оценка покажет срабатывание хоть на одной,
числа оракула изменятся законно, и его перепинивает владелец; иначе приёмка не
меняется ни в одной цифре.

## 7. Откат

Кода: `git revert` мерж-коммита. Данных: тот же адресный `--apply` старым
кодом — отпечаток сработавших записей возвращается к прежнему, и
`insert_calculation` делает прежнюю строку текущей (`reactivated`), новая
остаётся в истории закрытой. Схема не менялась; append-only сохранён; RAW и
`billable_area_m2` не трогались ни в одну сторону.

## 8. Что открыто — вопрос владельцу

1. **Короткое настоящее движение при применении** — вся августовская очередь (25
   из 25, включая три подтверждённых фантома). Закрыть её автоматически можно
   только с допуском: либо «сдвиг меньше X м / след меньше Y % RAW — не
   работа», либо семантикой «повторный проход по учтённой земле площадью не
   считается» (тогда ноль доказывает счётчик, и движение не важно). Оба —
   бизнес-правила: решение владельца и заранее зафиксированная проверка на
   другом периоде. Здесь не реализовано.
2. **Колонки `moving_application_*` кэша сводок** (только флаг, только поле 3,
   порог 1 м/с) решения не читают; выровнять — при следующем подъёме
   `V4_PARSER_VERSION`.
3. **Сентябрьский оракул** — см. §6.
4. Карточка записи на проверке не показывает цифры движения — их даёт
   `motion_eval.csv`. Показ на экране — отдельная UI-задача.
