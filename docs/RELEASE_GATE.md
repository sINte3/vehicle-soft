# RELEASE_GATE — что влито в `main`, но ещё не провалидировано

Один файл на весь проект. Его читают все треки, потому что друг друга они не
видят, а репозиторий видят.

**Правило.** Строка кладётся **последним коммитом внутрь PR** — тогда она
приезжает в `main` вместе с мержем сама собой (мерж-коммит, созданный кнопкой
GitHub, правок файлов содержать не может). Для задач Fable это обязательный
финальный шаг промпта. Кто закрыл проверки — удаляет свою строку.

**Прод-деплой разрешён только когда пуста таблица «Открытые пункты».** Она и
есть гейт; раздел «В работе, ещё не влито» — объявление по правилу 12, он ничего
не блокирует: там лежит то, чего в `main` ещё нет, и уехать на прод оно не может
по определению.

**В норме файл пуст.** По уставу проверка идёт до мержа, поэтому строка
появляется только как **остаток** — то, что пришлось смержить раньше проверки.
Если строки заводятся и снимаются через час, файл превращается в шум и на него
перестают смотреть.

**Дисциплина против конфликтов слияния.** Одна запись — ровно одна строка файла;
добавлять в конец своей секции; **никогда не переформатировать таблицу целиком и
не выравнивать столбцы пробелами**. Одно косметическое выравнивание — и следующий
мерж конфликтует по всему файлу.

Заведён 2026-07-24 после случая, когда инкремент 7 трека Запчастей уехал на
production попутно с релизом трека АЗС `c548c71`, минуя ~25 незакрытых проверок.
