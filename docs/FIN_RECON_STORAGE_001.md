# FIN-RECON-STORAGE-001 — неизменяемый снимок финансовой сверки операторов дронов

**Трек:** Дроны. **Ветка:** `claude/fin-recon-prompt-ry4xsx`, один Draft PR,
не мержится. **Состояние:** код и проверки готовы; staging не проверен —
`STAGING_PENDING_OWNER_RUN` до прогона ранбука владельцем
(`docs/FIN_RECON_STORAGE_001_RUNBOOK.md`).

В этом документе нет ни одного реального ФИО, суммы или файла: репозиторий
публичный. Реальный мартовский снимок, его пакет и контрольные ожидания
живут только в приватном пакете, который владелец получает по закрытому
каналу. Все тесты — на синтетике (месяц `2031-03`).

## 1. Что это и чего здесь нет

Финансовая сверка операторов за март 2026 проведена вне программы и
закончилась статусом **«сверен с исключениями»**. Задача — сохранить этот
результат так, чтобы он пережил потерю любой тестовой базы, и показать его
на staging только для чтения, не превращая staging в единственное
хранилище:

* **приватный пакет восстановления** — оригиналы, `snapshot.json`,
  манифест, SHA-256 каждого файла, контрольные ожидания;
* **хранилище в базе** — одиннадцать таблиц `fin_recon_*`, неизменяемых
  средствами самой базы;
* **импорт** одной командой оператора, одной транзакцией, с проверкой всего
  до первой записи;
* **экран «Дроны → Финансовая сверка»** — только чтение, только
  администратор; выгрузка XLSX с пометкой «не источник истины»;
* **восстановление в пустую базу** одной командой, с повтором всех
  контрольных чисел;
* **ранбук владельца** — восемь блоков PowerShell.

Не входит и не сделано: утверждение или закрытие марта (такой функции нет
вовсе), кассовое признание долгов, апрель, правка `drone_works` и любых
существующих таблиц, пересчёт DJI, production.

## 2. Решения и почему

| № | Решение | Почему |
|---|---|---|
| ФС1 | Снимок — данные, а не код. Ни одного мартовского числа в коде и шаблонах | будущие месяцы придут тем же контрактом; числа марта — ожидания конкретного снимка, они лежат в приватном пакете (`expectations/`) |
| ФС2 | Неизменяемость держит база: `UPDATE` и `DELETE` запрещены триггерами на всех таблицах, после печати к снимку нельзя добавить строку, поля утверждения не принимают значения | снимок, который поздняя правка могла бы тихо переписать, снимком не был бы |
| ФС3 | Моделей ORM нет; экран читает отдельным соединением `mode=ro`, пишет только импортёр на stdlib | `db.create_all()` создал бы таблицы пустыми на базе без миграции — дрейф без падения |
| ФС4 | Деньги и площади — десятичные строки (`Decimal`), без float. Неизвестное — `NULL` с типом `UNKNOWN`, и это держит `CHECK` | «неизвестная зарплата» и «ноль» — разные факты; на экране неизвестное — слово «неизвестно», не пустая ячейка |
| ФС5 | У каждого числа — доказательный тип: записано текстом, число книги, формула книги, расчёт реестра, трактовка владельца, выгрузка системы, неизвестно | сумма «признано выплаченным» и сумма «записано текстом» не смешиваются и не подменяют друг друга |
| ФС6 | Версии: тот же месяц, версия и хеш — повтор без единой записи; та же версия с другим содержимым — отказ; v2 обязана сослаться на хеш v1, причина записывается, v1 не меняется | история сверки не перезаписывается импортёром |
| ФС7 | Работа другого календарного месяца в книге месяца хранится связью; при загрузке соседнего месяца совпадение показывается **кандидатом** в межмесячный дубль в обе стороны, ничего не исключается автоматически | исключение по правдоподобию — бизнес-правило, которого нет |
| ФС8 | Снимок DJI — отдельная запись с датой снятия; живой DJI не читается | живая принятая площадь может измениться позже; исторический снимок — нет |
| ФС9 | Доступ — только `is_admin`; права модуля «Дроны» мало. `Cache-Control: no-store`. Формы загрузки нет. Пути файловой системы не выводятся. В XLSX текст, начинающийся с `= + - @`, табуляции или перевода строки, обезврежен апострофом | на экране ФИО, начисления и выплаты |
| ФС10 | Пакет адресуется содержимым: `blobs/<sha256>.<ext>`, пути ASCII, исходные имена — в манифесте | имя файла не может подменить содержимое; SHA-256 доказывает целостность битов, **не** подлинность операции и **не** подпись владельца |
| ФС11 | Экран на staging — через **изолированный клон** (отдельная папка, копия базы staging, порт 5052), а не выкладкой на сам staging | площадка 5051 занята пилотом DRONE-CARD-COVERAGE-001; выкладка сменила бы его код и подняла staging до `main` — задание это запрещает (§6 задания: «изолированный staging clone и точный план») |

Модули: `fin_recon/` (контракт, пакет, схема, импорт, чтение, сверка,

## 4. Контракт снимка `fin-recon-snapshot/1`

Верхний уровень: `schema`, `header`, `sources`, `metrics`, `operators`,
`payouts`, `works`, `anomalies`, `decisions`, `cross_period_links`, `dji`,
`vs`. Ключи каждого уровня — строго заданный набор: лишний или
недостающий ключ — отказ.

`fin_recon/contract.py` проверяет снимок целиком и возвращает **все**
нарушения, а не первое:

* статус только `RECONCILED_WITH_EXCEPTIONS`, `owner_approved_at` и
  `financially_closed_at` — `null`;
* у работы — ссылка на книгу (`BOOK_PRIMARY`), лист, строку и при
  необходимости часть составной строки; пара (источник, лист, строка,
  часть) уникальна; месяц работы — месяц одной из её дат; месяц книги —
  месяц снимка;
* у оператора: разбивка площади равна сумме его работ по (месяц работы,
  блок); итог признанного равен сумме выплат; разница равна «начислено
  минус признано»;
* выплата «трактовка владельца» обязана ссылаться на решение владельца;
  «записано текстом» — на текст и ячейку;
* каждая работа другого месяца обязана иметь межмесячную связь с той же
  площадью;
* тождества DJI: принято = RAW − исключено; исключено = автоматически +
  решениями администратора; решения администратора = сумма по решениям;
  корзины в сумме дают RAW и число вылетов;
* счётчики сверки с Vehicle Soft равны пересчёту по работам;
* контрольные показатели (`metrics`) пересчитываются из строк
  (`derived_checks`): число работ, операторов, аномалий, площади, начислено,
  записано текстом, признано, разница и другие; обязательные проверки —
  `REQUIRED_CHECKS`.

Хеш содержимого — SHA-256 канонического JSON (`sort_keys`, разделители
`(',', ':')`, `ensure_ascii=False`). Импорт после записи собирает снимок
обратно из строк базы и сверяет хеш **до** коммита.

## 5. Пакет `fin-recon-package/1`

```
snapshot.json  manifest.json  SHA256SUMS.txt  README.txt
blobs/<sha256>.<ext>          оригиналы без изменений
expectations/<имя>.json       контрольные ожидания (числа задания)
tools/                        приватный сборщик, который сделал снимок
```

`check-package` проверяет: `SHA256SUMS.txt` перечисляет ровно файлы на
диске и каждый хеш сходится; имя каждого блоба равно его SHA-256; JSON без
float и без повторных ключей; контракт снимка; манифест (строго заданные
ключи, хеши снимка, блобов, выходов); у источника «в пакете» есть блоб;
книга действительно лежит в своём исходном архиве (по хешам членов ZIP).
Один изменённый байт любого файла — отказ с понятной причиной.

Большой оригинал книги с фотографиями в пакет не входит и сборщику не
передавался: в манифесте он записан внешним источником без хеша. Его хеш
записывает блок 8 ранбука.

## 6. База: миграция `FIN_RECON_STORAGE_001`

Одиннадцать таблиц, 4 индекса, 34 триггера; чисто аддитивно — ни одна
существующая таблица, колонка или строка не трогается.

| Таблица | Что держит |
|---|---|
| `fin_recon_period_snapshot` | одна строка на (месяц, версия): статус, пустые поля утверждения, хеши содержимого, файла снимка и манифеста, канонический JSON, ссылка на предыдущую версию |
| `fin_recon_source` | исходные файлы с SHA-256 и ролью |
| `fin_recon_metric` | контрольные показатели: смысл, единица, доказательный тип |
| `fin_recon_operator_row` | по оператору: площадь, начислено, признано, разница |
| `fin_recon_payout` | записи о выдаче: текст книги или трактовка владельца |
| `fin_recon_work_row` | работы книг: источник, лист, строка, площадь, даты, месяц работы и книги, вердикт Vehicle Soft |
| `fin_recon_anomaly` | аномалии с идентификаторами и статусами реестра |
| `fin_recon_owner_decision` | решения владельца и контрольные заметки |
| `fin_recon_cross_period_link` | работы другого месяца внутри месяца книги |
| `fin_recon_dji_snapshot` | технический снимок DJI периода |
| `fin_recon_snapshot_seal` | печать: после неё к снимку нельзя добавить строку |

Миграция по образцу проекта: stdlib, `MIGRATION_ID`, реестр через
`migration_utils`, отказ с кодом 2 без базы (файл не создаётся),
предусловие (никаких объектов `fin_recon_*` без строки реестра) — иначе
код 1 и полный откат, одна транзакция, постусловия до записи в реестр,
ASCII-вывод. Четыре пути проверены тестами
(`tests/test_fin_recon_migration.py`).

## 7. Инструмент оператора `tools/fin_recon_storage.py`

| Команда | Что делает |
|---|---|
| `check-package --package DIR [--expect FILE]` | проверка пакета целиком; в базу не ходит |
| `import --db FILE --package DIR [--imported-by NAME]` | загрузка одной транзакцией; повтор — `ALREADY_IMPORTED`, ноль записей |
| `verify --db FILE --package DIR [--expect FILE]` | только чтение: база против пакета и ожиданий |
| `restore-test --package DIR --workdir DIR [--expect FILE]` | восстановление в **новую пустую** базу; повторный импорт не меняет файл базы ни на байт |
| `status --db FILE` | только чтение: какие снимки лежат в базе |

Коды выхода: 0 — PASS; 1 — непредвиденная ошибка; 2 — аргументы или нет
базы; 3 — конфликт версий; 4 — пакет негоден; 5 — миграция не применена;
6 — сверка не сошлась. Последняя строка вывода — `RESULT=...`, вывод
только ASCII. Сокращать флаги нельзя.

## 8. Экран и выгрузка

* `/drones/fin-recon` — список снимков: месяц книги, версия, статус,
  печать, число работ, операторов и аномалий.
* `/drones/fin-recon/<месяц>[?version=N]` — снимок: статус «Сверен с
  исключениями» рядом с «Финансово НЕ утверждён» и «НЕ закрыт»; открытые
  хозяйственные вопросы (аномалии «ОТКРЫТО»); итоги с доказательным типом
  каждого числа; операторы; работы с датами работы, книги и выдачи;
  аномалии; источники и решения; снимок DJI с оговоркой «принятая площадь
  — техническая, не основание для счёта и начисления»; сверка с Vehicle
  Soft; версия и происхождение; переходящие работы и кандидаты в
  межмесячный дубль.
* `/drones/fin-recon/<месяц>/export.xlsx` — шесть листов, на каждом
  первой строкой «НЕ ИСТОЧНИК ИСТИНЫ…» с хешем снимка; числа точные, формул
  нет.

Двуязычно (русский и узбекский кириллицей). Ни одной формы, ни одной
кнопки утверждения или загрузки. Пункт «Финансовая сверка» в полосе
раздела «Дроны» — только у администратора, перед «Отчётами».

Flask и идёт в полном прогоне `python -m unittest discover -s tests`.

Реальный март проверен приватно, вне репозитория (журнал — в приватном
комплекте): восстановление в пустую базу (183 строки, все проверки и 32

файл базы не изменился), экран RU и UZ и выгрузка на реальном снимке
(точное совпадение строк показателей, межмесячные связи, отсутствие путей
и элементов управления), отрицательные контроли на копии реального пакета
(подменённый байт реестра — отказ; изменённая v1 — конфликт без записи;
v2 — новая версия, v1 не изменилась).

## 10. Развёртывание и откат

Ранбук — `docs/FIN_RECON_STORAGE_001_RUNBOOK.md`: 1 проверка (только
чтение) → 2 код ветки в отдельной папке, архив, восстановление в пустую
базу → 3 клон staging (онлайн-копия базы staging, миграция и загрузка на
копии) → 4 запуск клона на 5052 → проверка экрана владельцем → 5 остановка
клона → 6 удаление клона; 7 второй экземпляр архива на другом диске; 8 хеш
большого оригинала. Production и базовый staging не меняются ни одним
блоком; каждый блок, касающийся сервера, сверяет HEAD и службы до и после.

Откат:

* **клон** — блоки 5 и 6; больше на сервере откатывать нечего;
* **код** (если PR когда-нибудь вольют) — `git revert` коммитов задачи в
  обратном порядке;
* **данные** — только после отката кода и при остановленной службе:
  `DROP TABLE` одиннадцати таблиц в порядке из докстринга
  `migrate_fin_recon_storage_001.py` и строка реестра; ни одна строка
  других таблиц не меняется;
* **приватный архив** не откатывается — это хранилище доказательств.

## 11. Что не проверено и что открыто

* **staging UAT не проводился** — нет доступа из сессии; статус
  `STAGING_PENDING_OWNER_RUN` до прогона блоков 1–5 владельцем;
* блоки на Windows PowerShell 5.1 исполняет только CI этого PR — на самом
  сервере ни один блок ещё не запускался;
* второй экземпляр архива не сделан (блок 7: выбор диска или сетевой
  папки — за владельцем);
* хеш большого оригинала с фотографиями не записан (блок 8, файл у
  владельца);
* экран живёт на клоне; на базовом staging 5051 и тем более на production
  его нет — это отдельное решение после освобождения площадки пилотом;
* расширение доступа за пределы администратора — отдельное решение (MVP —
  только администратор);
* апрель — следующий макроэтап после независимой приёмки хранения марта.
