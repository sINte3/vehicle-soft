# Проблемный регистр

Выходной артефакт фазы P1. **У каждой записи есть артефакт-доказательство** —
строка инвентаря, число из метрик или кадр обхода. Записи без артефакта в
регистр не попадают; это правило, а не формальность.

Источники:
`10-repo-inventory.json` (код) · `10-metrics/ux_metrics.json` (боевые данные) ·
`11-baseline/pages.json`, `a11y-baseline.json` (рендер, 320 кадров на четырёх
вьюпортах плюс прогоны на узбекском и под ролью без прав).

## Шкала тяжести

| | Значение |
|---|---|
| **B** blocking | мешает работе сегодня |
| **H** high | ухудшает ежедневную работу или портит данные |
| **M** medium | несогласованность; цена накапливается с каждым инкрементом |
| **L** low | полировка |
| **P** planned | сломано для сценария, который заявлен, но ещё не начался (мобильные) |

Цена: **S** — до ~40 строк CSS или один шаблон · **M** — компонент плюс
несколько шаблонов · **L** — общий файл или сквозная правка по модулям.

## Отрицательные результаты

Их важно записать: они закрывают гипотезы, которые иначе будут выдвинуты
заново.

**Узбекский язык не является причиной сломанной адаптивности.** Гипотеза из
метрик (M6: узбекские подписи на 19–47 % длиннее русских) предсказывала рост
числа переполнений. Отдельный прогон под администратором с `language='uz'`
дал **ноль новых переполнений** и 14 против 15 на мобильном. Величины
двигаются в обе стороны: `/wialon` +68 px, `/admin/audit` +20 px,
`/report` +15 px, но `/ref/equipment` −88 px, `/admin/users` −42 px.

Причина: переполнение определяется структурой таблицы — числом колонок и
шириной числовых и датных полей, — а не длиной подписей. При переполнении в
300–780 px прибавка в 20 % на подписях не меняет главного слагаемого.
Риск узбекского реален для **кнопок и подписей**, и проверять его надо, но в
причины PR-020 он не входит.

**Классический «AI-slop» в продукте не подтверждён.** Градиентов 5 на весь
проект, базовый шрифт 13 px, потолок шкалы 23 px, внешних шрифтов и CDN нет,
переходы 0,13–0,17 с. Гигантских заголовков, избыточного воздуха и
маркетинговой анимации нет. Подтверждённые дефекты этого класса другие и
перечислены выше: PR-013 (эмодзи вместо иконок), PR-006 (цветные свечения),
PR-005 (шесть радиусов), PR-004 (тринадцать брейкпоинтов).

## Что осталось незакрытым в P1

- **Реалистичный прогон под ролью `viewer`.** У фикстурного пользователя нет
  ни одной строки прав, поэтому 76 отказов из 80 — артефакт сидера, а не
  измерение. PR-045 от этого не зависит: петля в действии восстановления
  видна при любом наборе прав. Для остального нужны права модулей у
  `ux_viewer`.
- **Поведение таблиц на боевых объёмах.** 394 817 строк `fuel_transactions2`
  на эфемерном экземпляре не воспроизводятся. Проверяется на staging в P7.
- **Клавиатурная навигация и видимость фокуса** — axe их не ловит, нужен
  ручной проход по сценариям.
