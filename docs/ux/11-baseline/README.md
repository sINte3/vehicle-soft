# Визуальный базис — как снят и что в нём

Снято `tools/ux/shoot.mjs` с эфемерного экземпляра, поднятого
`tools/ux/serve_ephemeral.py`. **Ни staging, ни production не затрагивались.**
Спецификация обхода — `docs/ux/40-baseline-crawl-spec.md`.

## Что в каталоге

| Файл | Что в нём | В git |
|---|---|---|
| `routes.json` | список маршрутов обхода: 107 пригодных, 10 пропущенных с причиной | да |
| `pages.json` | по одной записи на «маршрут × вьюпорт»: HTTP-код, время, вес HTML, число и классы таблиц, inline-стили, глифы, формы, поля без доступного имени, горизонтальное переполнение | да |
| `a11y-baseline.json` | прогон axe-core по каждому маршруту: узлы по серьёзности и по правилам | да |
| `errors.json` | маршруты, отдавшие 4xx/5xx или упавшие | да |
| `desktop/ laptop/ tablet/ mobile/` | PNG, 80 маршрутов × 4 вьюпорта | **нет** |

Полная матрица кадров — регенерируемый артефакт объёмом около 70 МБ, в git не
кладётся (`.gitignore`). Пересоздаётся двумя командами:

```
python tools/ux/serve_ephemeral.py --port 5099 --rows 22 &
PLAYWRIGHT_BROWSERS_PATH=/opt/pw-browsers node tools/ux/shoot.mjs
```

Коммитятся только кадры, на которые ссылается проблемный регистр, — по мере
его наполнения, в `docs/ux/12-evidence/`.

## Что показал первый полный прогон

320 кадров, 80 маршрутов × 4 вьюпорта. Ошибок HTTP — одна
(`/drones/works/import/20/report`, 404: партии импорта с таким
идентификатором нет ни в фикстурах, ни на боевой базе).

### Адаптивность ломается только ниже 1024

**20 случаев горизонтального переполнения: 15 на `mobile`, 5 на `tablet`,
ноль на `desktop` и `laptop`.** Переполнение измерялось как
`documentElement.scrollWidth > clientWidth` — это прямое обнаружение, а не
оценка на глаз.

| Маршрут | mobile | tablet |
|---|---|---|
| `/ref/equipment` | **+780 px** | +406 px |
| `/fuel/balance-report` | +678 px | +304 px |
| `/admin/users` | +571 px | +197 px |
| `/admin/audit` | +444 px | +70 px |
| `/fuel/initial-balance` | +385 px | +11 px |
| `/ref/organizations` | +365 px | — |
| `/ref/customers` | +350 px | — |
| `/report` | +306 px | — |
| `/wialon` | +256 px | — |
| `/ref/work_types` | +192 px | — |
| `/deficiencies` | +107 px | — |
| `/wialon/report`, `/wialon/workload`, `/wialon/auto_match`, `/drones/reports/reconcile` | +65…+4 px | — |

`/ref/equipment` при ширине окна 390 px имеет ширину документа 1170 px —
страница втрое шире экрана. Это не «неудобно на телефоне», это неработающая
страница.

Показательно распределение: пять худших случаев — справочники и админские
таблицы, то есть экраны, которые до `--vs-*`-компонентов не доехали
(категории `D` и `E` в инвентаре). Модуль дронов, полностью построенный на
системе, даёт максимум +4 px. **Это прямая связь между принятием
дизайн-системы и работоспособностью адаптивной вёрстки, измеренная числом.**

### Доступность: нарушения на всех 80 маршрутах

Прогон axe-core (WCAG 2.0/2.1 уровни A и AA), десктопный вьюпорт:

| | Узлов |
|---|---|
| serious | **791** |
| critical | **367** |

| Правило | Узлов | Что значит |
|---|---|---|
| `color-contrast` | **768** | текст не проходит порог контраста AA |
| `label` | **245** | поле формы без связанной подписи |
| `select-name` | **122** | список без доступного имени |
| `link-in-text-block` | 7 | ссылка внутри текста отличается только цветом |
| `document-title` | 7 | у страницы нет `<title>` |
| `html-has-lang` | 7 | нет атрибута `lang` — **в двуязычном приложении** |
| `scrollable-region-focusable` | 2 | прокручиваемая область недостижима с клавиатуры |

Независимая от axe проверка форм даёт согласующееся число: **872 поля без
доступного имени на 41 странице из 80**. Худшие: `/drones/works` — 308,
`/drones/customers` — 110, `/admin/permissions` — 105.

`color-contrast` с 768 узлами связан с находкой инвентаря: 213 цветов
записаны мимо токенов, поэтому контраст перестаёт быть свойством пары
токенов и становится свойством конкретной строки — его нельзя ни проверить,
ни гарантировать централизованно.

### Inline-стили в отрендеренном виде хуже, чем в исходниках

В исходниках 2249 строк внутри `<style>`. В рендере к ним добавляются
**3121 атрибут `style=`** на 80 страницах. Худшие: `/drones/works` — 483,
`/drones/customers` — 276, `/admin/permissions` — 148, `/drones/units` — 146.

Отдельно: блок `<style>` присутствует на **всех 80 страницах** — он приходит
из `base_next.html`, то есть является частью оболочки, а не следствием
конкретной страницы.

### Пиктограммы

275 глифов в видимом тексте на 26 страницах из 80 — согласуется с 227
вхождениями в разметке (часть приходит из повторяющихся строк таблиц).

## Условия съёмки

Роль `ux_admin`, язык по умолчанию (русский), 80 маршрутов после отсева
`/api/*`, выгрузок и `logout`.

Вьюпорты выбраны так, чтобы попадать **внутрь** существующих веток CSS, а не
на их границы (в системе 13 брейкпоинтов):
`desktop` 1920×1080, `laptop` 1440×900, `tablet` 1024×768, `mobile` 390×844.

Детерминизм: анимации и переходы погашены, каретка скрыта, часовой пояс
`Asia/Tashkent`, локаль `ru-RU`, `deviceScaleFactor: 1`, ожидание
`networkidle` и `document.fonts.ready`, прокрутка сброшена перед съёмкой.
Это несущее требование, а не косметика: базис пересматривается после каждого
PR фазы миграции и сравнивается с предыдущим.

## Ограничения, которые надо знать при чтении

- **Данные синтетические.** Строки имеют длины, измеренные на боевой базе
  (p90 в рабочем случае, `max` на каждой десятой строке), и полные наборы
  статусных значений — но объёмы уменьшены. Поведение таблицы на 394 817
  строках `fuel_transactions2` этот базис **не проверяет**; это делается на
  staging в фазе P7.
- **Один язык и одна роль.** Прогоны на `lang=uz` и под ролью `ux_viewer`
  (состояния «нет прав») — отдельные, ещё не выполнены.
- **Дата привязана к дню съёмки.** Экраны по умолчанию показывают текущий
  день, поэтому кадры разных дней несравнимы напрямую: базис пересматривается
  целиком, а не частями.

## Две поправки, внесённые по результатам первого прогона

Обе — дефекты инструмента, а не продукта; записаны, чтобы не были внесены
заново.

1. **`/admin/audit` отдавал 500** — `no such table: audit_logs`. Таблица
   создаётся миграцией `migrate_sec003a_real.py` сырым SQL и модели
   SQLAlchemy не имеет, поэтому `db.create_all()` её не создаёт вовсе. Это
   пробел одноразовой базы, а не дефект интерфейса; без исправления он попал
   бы в отчёт как ошибка страницы. Таблица создаётся в
   `serve_ephemeral.create_non_model_tables()`.
2. **Результаты axe сериализовались пустыми.** Вторым аргументом
   `JSON.stringify` передавался массив ключей — а это **replacer**, то есть
   белый список свойств: `bySeverity` и `rules` вырезались, оставляя `{}` по
   каждому маршруту. Порядок ключей теперь задаётся пересборкой объекта.

Оставшийся известный пропуск: `/drones/works/import/20/report` отдаёт 404 —
партии импорта с таким идентификатором в фикстурах нет
(`drone_work_imports` пуст и на боевой базе).
