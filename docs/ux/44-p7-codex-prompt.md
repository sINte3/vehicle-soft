## Как ты входишь в систему

**Весь прогон — headless. Видимое окно браузера не открывай никогда и не
проси человека войти руками.** Машина — Windows Server; процесс, запущенный
не из интерактивной сессии, окна не покажет, и ты упрёшься в тупик, которого
нет. Вход выполняет твой скрипт, подставляя логин и пароль в форму:

```js
await page.goto(BASE + '/login', { waitUntil: 'domcontentloaded' });
await page.fill('input[name="username"]', LOGIN);
await page.fill('input[name="password"]', PASSWORD);
await Promise.all([
  page.waitForLoadState('domcontentloaded'),
  page.click('form.vs-login-form button[type="submit"]'),
]);
if (page.url().includes('/login')) throw new Error('вход не удался: ' + LOGIN);
```

Логин и пароль нужны тебе **текстом** — именно чтобы подставить их сюда.

## Первое, что надо сделать: спросить пароль

Прогон идёт под учётной записью **`admin`** — под ней видны все проверяемые
экраны.

**Спроси у владельца пароль текстом и дождись ответа.** Не подбирай, не
угадывай, не бери из кода, не пытайся переиспользовать чужую уже

**Исходный язык этой учётной записи — РУ.** Его и надо вернуть в конце
прогона.

**Под `admin` доступно всё, включая удаление.** Поэтому правило кликов ниже
здесь не формальность: случайное нажатие действия под администратором
уничтожает данные, а не показывает ошибку.

## Язык интерфейса: как его менять и почему ровно три раза

Язык берётся **из учётной записи**, а не из адреса: параметр языка в URL
приложение игнорирует, и прогон «на узбекском» через `?lang=uz` снимется
по-русски, ничего об этом не сказав. Отдельных учётных записей под два языка
на этой площадке нет — язык переключается кнопкой **УЗ / РУ** в шапке.

**Эта кнопка пишет в базу.** Она отправляет форму на `set_language_route`,
который выполняет `current_user.language = lang` и коммитит. То есть каждое
нажатие — изменение данных, а не чтение. Поэтому:

**Разрешено не больше трёх нажатий на весь прогон — а при исходном РУ их
достаточно двух:**

1. открой любой экран и **прочитай, какой язык активен** (кнопка с классом
   `is-active`). Ожидается **РУ**. Запиши это значение — его надо вернуть;
2. если активен не РУ — нажми **РУ**. Если РУ уже активен, **не нажимай**:
   лишнее нажатие — лишняя запись в базу. Затем обойди все адреса, сними
   кадры, собери подписи;
3. нажми **УЗ** → обойди те же адреса ещё раз, собирая **только тексты
   подписей** (кадры в узбекском проходе нужны лишь там, где нашлось
   расхождение);
4. **верни язык, записанный на шаге 1** — при ожидаемом РУ это одно нажатие.

Селекторы (кнопки есть на любом экране после входа):

```js
await page.click('form.vs-lang button[value="ru"]');   // русский
await page.click('form.vs-lang button[value="uz"]');   // узбекский
// какой язык активен сейчас:
const active = await page.getAttribute('form.vs-lang button.is-active', 'value');
```

Нажимай именно кнопку в разметке, а не собирай POST руками: в форме есть
`csrf_token`, и запрос без него не пройдёт.

**Переключать язык на каждой странице запрещено.** Это дало бы сотни записей
в базу вместо трёх. Порядок «переключил один раз → прошёл весь список»
обязателен.

В отчёте прямо напиши: под какой учётной записью шёл прогон, какой язык был
у неё до начала, сколько раз ты переключал язык и вернул ли исходный в конце.

Заодно спроси и запиши: **короткий хеш коммита**, развёрнутого на площадке
(владелец получил его командой `git rev-parse --short HEAD`). Без хеша отчёт
не принимается: неизвестно, что именно снималось.

## Чего делать НЕЛЬЗЯ. Прочитай прежде, чем открыть первую страницу

Площадка держит **копию боевой базы**. Правила:

| Действие | Можно? |
|---|---|
| Открыть адрес из списка через `page.goto()` | **да** |
| Нажать кнопку действия | **нет** |
| Отправить форму | **нет** |
| **Перейти по ссылке** (клик по `<a>`) | **нет** |
| Создать, изменить, удалить что-либо | **нет** |
| Править код приложения, коммитить | **нет** |

**Во всём прогоне `page.click()` разрешён ровно по двум селекторам, и
никаким другим:**

```
form.vs-login-form button[type="submit"]     вход, один раз
form.vs-lang button[value="ru"|"uz"]         язык, всего три нажатия
```

Всё остальное открывается только через `page.goto()`. Если тебе кажется, что
для проверки нужен ещё один клик, — не делай его, а напиши в отчёте, что
именно осталось непроверенным и почему.

Переключатель языка записывает `current_user.language` в базу — это
единственное допущенное изменение данных, и оно возвращается в исходное
состояние в конце прогона.

**«Только GET» здесь не равно «безопасно».** В истории проекта три
исправленных дефекта «GET с побочным эффектом»: экспорт Wialon, выгрузка
workload и **выход из системы по GET**. Поэтому обход ходит строго по
явному списку адресов, а не по ссылкам со страницы: краулер, гуляющий по
ссылкам, рано или поздно нажмёт выход или запустит тяжёлую выгрузку на
боевом объёме.

Адреса со словами `export`, `download`, `logout`, `.xlsx`, `.pdf`, `/pdf`
исключаются из списка, даже если попались в разметке.

### E. Двуязычие

Собери подписи одного и того же адреса **в русском проходе и в узбекском**
(вьюпорт `laptop` достаточно) и сравни. Что брать:

```js

             + ' .vs-empty-sub, .vs-table-scope, option[value=""]';
const labels = await page.evaluate((sel) =>
  [...document.querySelectorAll(sel)]
    .map(n => n.textContent.replace(/\s+/g, ' ').trim())
    .filter(x => x && x.length < 90), LABELS);
```

Сравнивай **по позиции**: `labels_ru[i]` против `labels_uz[i]`.

Подпись, **одинаковая в обоих языках**, — кандидат в дефекты. Совпадение
допустимо и в отчёт не идёт только для:

- брендов и технических обозначений: `Wialon`, `Excel`, `PDF`, `IP`, `№`,

- слов, совпадающих в двух языках: «Логин», «Роль», «Модель», «Категория»,

### G. Реальные объёмы против синтетики

**Это то, ради чего вообще нужен staging.** Вся разработка мерялась на
одноразовой базе с 22 строками в таблице; здесь настоящие данные. Смотри
именно то, что от объёма зависит:

- таблицы в тысячи строк: не растянулась ли страница, работает ли прокрутка
  таблицы, видна ли шапка. Назови **самую большую таблицу и число строк в
  ней**;
- колонки со свободным текстом (описание в журнале действий, примечания):
  не разъехалась ли таблица от одной аномально длинной строки. Назови
  **максимальную длину текста в такой колонке**;
- подписи охвата под таблицами вида «Показано: N / M» — верны ли они на
  боевом объёме;
- `/admin/audit` — там тысячи записей, и это главный кандидат на проблемы
  объёма;
- время загрузки самых тяжёлых страниц — назови числом, хотя бы грубо.

Ответ вида «всё хорошо» здесь не принимается. Нужны числа.

**Ноль в показателе — это данные, а не дефект.** На главной панели период по
умолчанию — сегодняшний день, и если за сегодня ввода не было, там честные
нули. Пустой экран считается дефектом, только если данные за период есть, а
экран их не показывает. Объёмы ищи там, где они накоплены: журнал действий,
справочники техники и организаций, заявки на запчасти, вылеты дронов.

## Как мерить, чтобы измерению можно было верить

- **Скриншот сам по себе ничего не доказывает.** Число, снятое из DOM,
  доказывает. Где можно измерить — измеряй, а не смотри.
- **Проверка, дающая одинаковый результат при верном и неверном коде,
