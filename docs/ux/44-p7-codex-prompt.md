## Первое, что надо сделать: спросить учётные записи

Тебе нужны **две** учётные записи площадки:

- одна, у которой язык интерфейса **русский**;
- одна, у которой язык интерфейса **узбекский**.

**Спроси у владельца логины и пароли и дождись ответа.** Не подбирай, не
угадывай, не бери из кода.

**Почему две.** Язык интерфейса берётся из **учётной записи**, а не из
адреса. Параметр языка в URL приложение игнорирует: прогон «на узбекском»
через `?lang=uz` снимется по-русски и никак об этом не сообщит. Значительная
часть этой проверки — именно двуязычие, и одной учётной записью она не
делается.

Если владелец говорит, что второй учётной записи нет, — прогоняй одну и
**напиши в отчёте, что двуязычие не проверялось**. Не выдавай два одинаковых
прогона за проверку двух языков.

Заодно спроси и запиши: **короткий хеш коммита**, развёрнутого на площадке
(владелец получил его командой `git rev-parse --short HEAD`). Без хеша отчёт
не принимается: неизвестно, что именно снималось.

## Чего делать НЕЛЬЗЯ. Прочитай прежде, чем открыть первую страницу

Площадка держит **копию боевой базы**. Правила:

| Действие | Можно? |
|---|---|
| Открыть адрес из списка через `page.goto()` | **да** |
| Нажать кнопку действия | **нет** |
| Отправить форму | **нет** |
| **Перейти по ссылке** (клик по `<a>`) | **нет** |
| Создать, изменить, удалить что-либо | **нет** |
| Править код приложения, коммитить | **нет** |

Единственные разрешённые клики — вход в систему на `/login`.

**«Только GET» здесь не равно «безопасно».** В истории проекта три
исправленных дефекта «GET с побочным эффектом»: экспорт Wialon, выгрузка
workload и **выход из системы по GET**. Поэтому обход ходит строго по
явному списку адресов, а не по ссылкам со страницы: краулер, гуляющий по
ссылкам, рано или поздно нажмёт выход или запустит тяжёлую выгрузку на
боевом объёме.

Адреса со словами `export`, `download`, `logout`, `.xlsx`, `.pdf`, `/pdf`
исключаются из списка, даже если попались в разметке.

## Что проверить

### A. Открываемость

Каждый адрес отдаёт **200** и не редиректит на `/login`. Всё, что отдало
4xx/5xx или увело на вход, — в отчёт с кодом и адресом.

### B. Ошибки страницы

На каждом адресе собери `console` уровня `error` и события `pageerror`.
Ожидание — **ноль**. Любая ошибка JavaScript — в отчёт с текстом и адресом.

### C. Съёмка

Под **русской** учётной записью, полная страница (`fullPage: true`),
`deviceScaleFactor: 1`, четыре вьюпорта:

| имя | ширина × высота |
|---|---|
| `laptop` | 1440 × 900 |
| `tablet` | 1024 × 768 |
| `narrow` | 600 × 900 |
| `mobile` | 390 × 844 |

Файлы: `C:\qa\ui-p7\shots\<slug>-<viewport>.png`. Итого около 320 кадров.

Перед каждым кадром отключи анимации, иначе одинаковые страницы будут давать
разные кадры:

```js
await page.addStyleTag({ content: `
  *, *::before, *::after {
    animation-duration: 0s !important; animation-delay: 0s !important;
    transition-duration: 0s !important; transition-delay: 0s !important;
    caret-color: transparent !important;
  }` });
await page.evaluate(() => window.scrollTo(0, 0));
```

Под **узбекской** учётной записью кадры снимать не нужно — она нужна для
пункта E. Сними её кадры только для тех экранов, где нашлось расхождение.

### D. Горизонтальное переполнение

На каждом адресе и каждом вьюпорте:

```js
const overflow = await page.evaluate(() => {
  const de = document.documentElement;
  return de.scrollWidth > de.clientWidth + 1;
});
```

Ожидание — `false` везде. Это измерение из DOM, а не взгляд на картинку:
на кадре «страницу вынесло за край окна» и «страница просто другая»
выглядят одинаково.

### E. Двуязычие

Открой **один и тот же адрес** под русской и под узбекской учётной записью
(вьюпорт `laptop` достаточно) и сравни подписи. Что брать:

```js
const LABELS = '.vs-label, .vs-card-title, .vs-btn, th, .vs-empty-title,'
             + ' .vs-empty-sub, .vs-table-scope, option[value=""]';
const labels = await page.evaluate((sel) =>
  [...document.querySelectorAll(sel)]
    .map(n => n.textContent.replace(/\s+/g, ' ').trim())
    .filter(x => x && x.length < 90), LABELS);
```

Сравнивай **по позиции**: `labels_ru[i]` против `labels_uz[i]`.

Подпись, **одинаковая в обоих языках**, — кандидат в дефекты. Совпадение
допустимо и в отчёт не идёт только для:

- брендов и технических обозначений: `Wialon`, `Excel`, `PDF`, `IP`, `№`,
  `OK`, `TELEGRAM`;
- слов, совпадающих в двух языках: «Логин», «Роль», «Модель», «Категория»,
  «Импорт», «Маппинг», «Техника», «Каталог», «ФАЙЛ»;
- терминов, которые владелец назвал одинаковыми: **«Фильтр», «Объект»,
  «Модуль»**.

**Названия организаций, техники, логины пользователей — это данные, а не
подписи.** Их совпадение нормально и в отчёт не идёт. Если в списке подписей
оказалось название организации (например, в заголовке карточки на
`/wialon/report`) — исключи этот узел и скажи, что исключил.

**Особое внимание модулю Виалон** (`/wialon`, `/wialon/mapping`,
`/wialon/auto_match`, `/wialon/report`) и экрану `/admin/audit`: смешанные
языки нашлись именно там, и их чинили последними.

### G. Реальные объёмы против синтетики

**Это то, ради чего вообще нужен staging.** Вся разработка мерялась на
одноразовой базе с 22 строками в таблице; здесь настоящие данные. Смотри

- таблицы в тысячи строк: не растянулась ли страница, работает ли прокрутка
  таблицы, видна ли шапка. Назови **самую большую таблицу и число строк в
  ней**;
- колонки со свободным текстом (описание в журнале действий, примечания):
  не разъехалась ли таблица от одной аномально длинной строки. Назови
  **максимальную длину текста в такой колонке**;
- подписи охвата под таблицами вида «Показано: N / M» — верны ли они на
  боевом объёме;
- `/admin/audit` — там тысячи записей, и это главный кандидат на проблемы
  объёма;
- время загрузки самых тяжёлых страниц — назови числом, хотя бы грубо.

Ответ вида «всё хорошо» здесь не принимается. Нужны числа.

## Как мерить, чтобы измерению можно было верить

- **Скриншот сам по себе ничего не доказывает.** Число, снятое из DOM,
  доказывает. Где можно измерить — измеряй, а не смотри.
- **Проверка, дающая одинаковый результат при верном и неверном коде,
  проверкой не является.** Прежде чем написать «ноль нарушений», убедись,
  что проверка вообще способна отличить два случая: например, что селектор
  подписей действительно что-то находит, а не возвращает пустой список.
  Пустой список даёт «ноль расхождений» на любом коде.
- Если сравниваешь два прогона — убедись, что они шли на одном коммите и на
  одних данных.
