# P1 · Спецификация визуального обхода Vehicle Soft

Документ одновременно **спецификация задачи** и **готовый промт для агента**.
Раздел «Промт» ниже самодостаточен: его можно передать в новую сессию без
остального контекста.

Процедура и обоснования — `docs/ux/00-workflow.md`. Состояние трека —
`docs/tracks/ui.md`.

---

## 1. Зачем это, и почему нельзя обойтись репозиторием

Четыре причины, каждая опирается на измеренный факт:

1. **Каскад не читается из исходников.** 2292 строки inline-`<style>` в 38
   шаблонах переопределяют дизайн-систему постранично. Какое правило победит
   на конкретном элементе — вопрос рендера, а не чтения.
2. **Слой совместимости делает разметку неоднозначной.** Одна и та же разметка
   выглядит по-разному в зависимости от того, какой набор переменных
   разрешился. Предыдущий аудит уже поймал такой дефект — `fuel/cards.html` с
   `var(--text-muted)`, не определённой в области видимости: код выглядит
   корректным, рендер — нет.
3. **Плотность, переполнение и переносы не выводятся из кода.** Восемь
   брейкпоинтов без объявленной шкалы. В `tools/` уже лежит
   `measure_drone_card_wrap.py`, написанный из-за переноса денежной суммы
   внутри карточки — проект этим обжигался.
4. **Длина реальных строк определяет ширину колонок.** Двуязычность
   (русский / узбекская кириллица) даёт разброс длины подписей, который на
   выдуманных данных не воспроизводится.

## 2. Режимы запуска

Обход имеет **два режима с разными правилами**. Путать их нельзя.

| | `ephemeral` — основной | `remote` — вторичный |
|---|---|---|
| Площадка | приложение, поднятое из `tests/harness.py` на одноразовой SQLite во временном каталоге | staging `10.103.25.14:5051`, когда площадка свободна |
| База | выбрасывается после прогона | чужая, не трогать |
| Клики по действиям | **разрешены** — база одноразовая, нужны состояния валидации и ошибок | **запрещены** |
| Отправка форм | разрешена | **запрещена** |
| Переход по ссылкам | разрешён | **запрещён** — только `goto` по списку |
| Кого покрывает | ~95 % аудита | реальные объёмы данных |

**Production (`5050` / `app.vehiclesoft.pp.ua`) в этой спецификации не
участвует.** Если он когда-либо понадобится — только режим `remote`, только по
белому списку URL из `docs/ux/11-baseline/prod-allowlist.txt`, утверждённому
владельцем, и **только потому, что переход по ссылкам там опасен**: в истории
проекта три исправленных дефекта «GET с побочным эффектом»
(`RELEASE_AUDIT_GET_SIDE_EFFECT_001` — экспорт Wialon, `_002` — выгрузка
workload, `_003` — logout по GET). «Только GET» здесь **не** равно «безопасно».

## 3. Что должно получиться

```
docs/ux/11-baseline/
  INDEX.md                      таблица: маршрут × вьюпорт × роль × язык → файл

      <route-slug>.png
  states/
      <route-slug>--<state>.png
```

## 4. ПРОМТ ДЛЯ АГЕНТА

> Скопировать начиная отсюда.

### Задача

Ты снимаешь визуальный базис ERP-системы Vehicle Soft для UX-аудита.
Ты **не меняешь дизайн, не правишь шаблоны, не «улучшаешь» ничего**.
Твой результат — скриншоты, JSON-метрики и список аномалий. Любое желание
поправить найденный дефект записывается в `errors.md`, а не в код.

### Что за система

Flask 3 + Jinja2, серверный рендеринг. **Ни одного фронтенд-фреймворка**,
ни одного внешнего CDN, шрифты системные. Стили — один файл
`static/css/design-system.css` (1365 строк, 90 CSS-переменных) плюс
inline-`<style>` в 38 шаблонах. 86 шаблонов, ~195 маршрутов. Интерфейс
двуязычный: русский и узбекский **кириллицей**.

Модули: техника и ежедневный ввод, наряды, запчастичный склад, топливо/АЗС
(интеграция Topaz), дроны DJI, Wialon, справочники, администрирование.

### Подготовка среды

```bash
node --version      # ожидается v22+
ls /opt/pw-browsers # chromium уже установлен
```

- **`playwright install` не запускать.** Браузеры предустановлены.
  Использовать `PLAYWRIGHT_BROWSERS_PATH=/opt/pw-browsers`; если версия
  пакета не совпадает с установленной сборкой — задать
  `executablePath: '/opt/pw-browsers/chromium'`.
- Node-инструмент живёт в `tools/ux/` со своим `package.json`.
  **`requirements.txt` не трогать** — это dev-инструмент, а не зависимость
  приложения. `tools/ux/node_modules/` — в `.gitignore`.
- Python-пакет `playwright` **не устанавливать**.

### Как поднять приложение (режим `ephemeral`)

`tests/harness.py` уже собирает **настоящее** приложение через
`app.create_app()`, но на одноразовой SQLite во временном каталоге и с
одноразовой папкой загрузок. Ни `instance/transport.db`, ни staging, ни
production при этом не затрагиваются.

Нужно написать два файла:

1. **`tools/ux/seed_ux_fixtures.py`** — наполняет одноразовую базу данными
   **реалистичной формы**: не выдуманными, а с длинами строк и объёмами из
   `docs/ux/10-metrics/ux_metrics.json` (выгрузка с боевой базы, содержит
   только длины и счётчики, без значений). Обязательно:
   - подписи на русском **и** на узбекской кириллице длиной около p90/p99 из
     метрик — короткие подписи скрывают ровно те дефекты, которые ищем;
   - денежные и площадные величины порядка `15 878.64` — на них проект уже
     ловил перенос внутри карточки;
   - все значения статусных полей из раздела `enums` метрик — иначе часть
     бейджей не отрендерится ни разу;
   - число строк, достаточное для включения пагинации и горизонтального
     переполнения таблиц, но не больше: цель — воспроизвести поведение, а не
     нагрузку;
   - по одному пользователю на каждую роль: `admin`, `operator`, `viewer`,
     `mechanic` (константы в `models.py`).
2. **`tools/ux/serve_ephemeral.py`** — поднимает это приложение на локальном
   порту и печатает URL. Импорт `app` допустим **только** здесь и только через
   механизм `tests/harness.py`: `app = create_app()` вызывает
   `db.create_all()` на импорте, поэтому любой другой скрипт, импортирующий
   `app`, становится писателем — это запрещено правилами проекта.

### Список маршрутов — откуда берётся

**Не переходом по ссылкам.** Из `app.url_map`: взять все правила с методом
`GET`, отбросить `static`, отбросить требующие параметров, которые нечем
заполнить, и для параметризованных (`/<int:id>`) подставить id сущностей,
созданных сидером. Результат сохранить в `docs/ux/11-baseline/routes.json`
**до** начала съёмки — это и есть контракт покрытия.

Причина: обход по ссылкам недетерминирован (набор ссылок зависит от прав и
данных), не воспроизводится между прогонами и не даёт понять, что пропущено.

### Матрица съёмки

**Вьюпорты — 4.** Значения выбраны так, чтобы попадать *внутрь* существующих
веток CSS, а не на их границы (в системе 8 брейкпоинтов: 1280, 1200, 1100,
900, 768, 720, 640, 480):

| Имя | Размер | Что проверяет |
|---|---|---|
| `desktop` | 1920 × 1080 | основной рабочий режим |
| `laptop` | 1440 × 900 | ниже `--vs-content-max: 1520px` — поведение контейнера |
| `tablet` | 1024 × 768 | между 1100 и 900 |
| `mobile` | 390 × 844 | ниже 768 — сайдбар выходит из потока |

**Роли — 2 прохода:** `admin` (видит всё) и `viewer` (минимальные права —
даёт состояния «нет доступа», которые иначе не снять).

**Языки:** весь набор — на русском. Дополнительно **на узбекском** — сайдбар,
топбар и по одному самому плотному экрану каждого модуля: узбекская кириллица
даёт другую длину подписей, и именно там ломаются колонки и кнопки.

**Оценка объёма:** ~86 маршрутов × 4 вьюпорта = ~344 кадра базовой матрицы,
плюс проход `viewer`, плюс узбекское подмножество, плюс состояния из
следующего раздела. Порядок — 500–600 файлов.
Если суммарный вес превысит ~60 МБ — конвертировать в WebP и записать
фактические цифры в `run.json`; **не молчать об усечении**: если какая-то
часть набора не снята, это отдельной строкой в `INDEX.md`.

### Состояния, которые не снимаются простым `goto`

Снимать в режиме `ephemeral`; в `remote` пропускать.

- **Оболочка:** сайдбар развёрнутый и свёрнутый (`--vs-side-w-col: 74px`);
  мобильное меню открыто; меню пользователя открыто; переключатель языка;
  `skip-link` в фокусе (первый `Tab` на странице).
- **Таблицы:** заголовок при прокрутке вниз; горизонтальное переполнение
  (кадр с прокруткой вправо до упора); открытое меню действий строки;
  активная сортировка; пагинация на не-первой странице.
- **Формы:** пустая; заполненная; **после отправки с ошибкой валидации**;
  поля обязательные и заблокированные. Минимум на `daily_entry`,
  `spare_part_form`, `work_order_form` — это три самые тяжёлые формы
  (`daily_entry.html` несёт 387 строк собственного CSS и 337 строк
  собственного JS).
- **Диалоги:** каждое модальное окно и подтверждение — открытым.
- **Состояния данных:** пусто (отфильтровать заведомо пустым запросом),
  загрузка (если есть индикатор), ошибка (маршрут с заведомо неверным id),
  нет прав (проход `viewer`).
- **Иконки:** отдельным кадром — участки с эмодзи в разметке. Их 228 вхождений
  и 43 различных глифа; самые насыщенные:
  `spare_part_detail` (29), `index` (19), `spare_parts_desk` (18),
  `wialon_mapping_list` (10).

### Детерминизм

Без этого повторный прогон даст ложные диффы, и вся визуальная QA
обесценится.

- отключить анимации и переходы (`prefers-reduced-motion` + инъекция CSS
  `*{animation:none!important;transition:none!important;caret-color:transparent}`);
- фиксированный часовой пояс и локаль; при наличии «сейчас» на экране —
  подменить время;
- `deviceScaleFactor: 1`, `fullPage: true`;
- ждать `networkidle` **и** отсутствие незавершённых шрифтов
  (`document.fonts.ready`);
- имя файла — детерминированный слаг маршрута
  (`/fuel/transactions` → `fuel-transactions.png`);
- прокрутку перед `fullPage`-съёмкой сбрасывать в начало.

### Доступность

В том же прогоне: `@axe-core/playwright` на каждом маршруте.
В `a11y-baseline.json` записать **числа** по severity и по маршрутам, а не
формулировку «есть проблемы». Дополнительно вручную (это axe не ловит):
проходимость по `Tab` в оболочке и в одной форме, видимость кольца фокуса,
размер зоны попадания иконочных кнопок.

### Что фиксировать помимо кадров

Для каждого маршрута в `INDEX.md`: HTTP-код, время ответа, вес HTML,
число `<table>` и их классы, наличие inline-`<style>`, число вхождений эмодзи,
горизонтальное переполнение `document.body` на каждом вьюпорте (булево —
это прямое обнаружение сломанной адаптивности).

### Границы

- Ничего не менять в `templates/`, `static/`, `*.py` приложения.
- Не запускать `playwright install`.
- Не добавлять зависимости в `requirements.txt`.
- Не импортировать `app` нигде, кроме `tools/ux/serve_ephemeral.py`.
- В режиме `remote` — ни одного клика по действию, ни одной отправки формы,
  ни одного перехода по ссылке.
- Найденные дефекты — в `errors.md`, не в код.

### Критерии готовности

1. `routes.json` создан **до** съёмки и покрывает все GET-маршруты, кроме
   явно перечисленных исключений с указанием причины.
2. **Ноль маршрутов с необъяснённой ошибкой рендера**; каждый 4xx/5xx имеет
   строку в `errors.md` с причиной.
3. Каждый маршрут из `routes.json` представлен на всех 4 вьюпортах, либо в
   `INDEX.md` есть строка, почему нет.
4. `a11y-baseline.json` содержит числа по severity.
5. Повторный прогон на том же коммите даёт **побайтово те же файлы** для
   неизменившихся страниц. Если нет — детерминизм не настроен, и до его
   настройки базис непригоден для сравнения до/после.
6. `INDEX.md` заполнен целиком; усечения названы явно.

> Конец промта.

## 5. Связь с остальными фазами

Результат этого обхода — вход для `docs/ux/12-problem-register.md`: каждая
запись реестра дефектов обязана ссылаться минимум на один кадр или строку
инвентаря. Записи без артефакта в реестр не попадают.

Тот же скрипт повторно запускается на каждом PR фазы миграции (P6) и даёт
диффы до/после — поэтому пункт 5 критериев готовности (побайтовая
воспроизводимость) не косметический, а несущий.
