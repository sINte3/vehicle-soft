# DJI-AREA-48H: решение по площади

Что исследование установило, чего оно НЕ установило, и какое правило расчёта
из этого следует. Документ фиксирует доказательную базу без завышения:
утверждения разделены на доказанные, поддержанные данными и недоказанные, и
третья группа здесь ровно так же важна, как первая.

Реализация решения — `DRONE-USEFUL-AREA-001`. Смотри `docs/tracks/drones.md`.

## 1. Выборка

Один день, 2026-06-05, собранный одним живым прогоном режима `--area-48h`.

| Величина | Значение |
|---|---|
| вылетов | 168 |
| пространственно связанных работ | 16 |
| вылетов без записанной ширины захвата | 32 из 168 |
| контур однозначно найден | 7 работ |
| контур неоднозначен | 5 работ |
| контур не найден | 4 работы |

Работа определена пространственно: одна машина, один локальный день (UTC+5),
пересекающиеся рамки маршрутов. `mission_uuid` в определении работы **не
участвует**: его семантика не доказана.

## 2. Что доказано на данных

- **Площадь DJI больше площади полосы всего собственного маршрута** у 108 из
  136 вылетов с известной шириной. То есть `new_work_area` описывает больше,
  чем геометрия этого вылета.
- **Повтор одного и того же значения площади внутри одной работы** найден в
  9 из 16 работ.
- **Простая сумма строк DJI превышает геометрическую оценку** в 15 из 16
  работ.
- **Перекрытие полос объясняет медианно 8,6 %** расхождения между суммой
  независимых полос и их объединением.
- **Движение вне контура объясняет медианно 27,3 %** расхождения.

## 3. Что НЕ доказано

- **Точная внутренняя формула DJI.** Накопительная трактовка (`new_work_area`
  как нарастающий итог работы) лучше совпала в 12 работах, повылетная — в 3.
  Ни одна не объясняет все 16, поэтому формула поставщика остаётся
  неизвестной, а не «скорее всего накопительной».
- **Признак включённого насоса.** Его в источнике нет. Неизвестное
  protobuf-поле №3, wire type 0, найдено в 143 из 168 вылетов, присутствует
  постоянно вдоль каждого такого маршрута и отсутствует в 25 вылетах. Его
  семантика — `UNKNOWN_SEMANTICS`. **Как признак распыления или рабочего
  участка оно не используется** и использоваться не будет, пока значение не
  установлено.

Отсюда главное ограничение показателя: он геометрический. «Рабочий проход» —
это вывод из формы маршрута, а не наблюдение за работой насоса.

## 4. Опорные числа

Одинаковая подвыборка: **62 вылета с записанной шириной в 7 работах с
однозначным контуром**.

| Величина | Га |
|---|---|
| сумма строк DJI | 69,1704 |
| сумма независимых полос | 35,3228 |
| объединение полос | 30,8378 |
| все полосы внутри контура | 15,9773 |
| **рабочие проходы внутри контура** | **14,5624** |

Каждый шаг сверху вниз отнимает одну названную причину: перекрытие полос
(35,3228 → 30,8378), движение вне контура (30,8378 → 15,9773), холостой ход
внутри контура (15,9773 → 14,5624).

**14,5624 га не является полным итогом этих семи работ.** Ещё у 23 их вылетов
ширина отсутствует, и вклад этих вылетов не посчитан ничем. Число нельзя
читать как «семь работ обработали 14,56 га».

## 6. Принятое правило расчёта

Показатель называется **«Расчётная полезная площадь, га»** (узбекский
кириллицей: **«Ҳисобий фойдали майдон, га»**), техническое имя
`estimated_useful_area_ha`, версия правил `useful-area-v1`:

```text
estimated_useful_area_ha =
    area(
        union(buffer(work_segments, spray_width / 2))
        intersect field_polygon
    ) / 10000
```

Проверенные параметры версии:

```text
cell_m = 0.5
gap_m = 60.0
min_step_m = 0.05
turn_deg = 25.0
min_pass_m = 20.0
contour_margin_m = 25.0
inside_share_min = 0.5
max_grid_cells = 24000000
```

Параметры, версия алгоритма и собственная погрешность расчёта сохраняются
вместе с каждым числом: число без объяснимой версии правил не хранится.

## 7. Что показатель НЕ заменяет

Исходное `DroneFlight.area_ha`, полученное из DJI `new_work_area`, **остаётся
без изменения**. Оно не переименовывается в полезную площадь, не
перезаписывается и не подменяется новым результатом. По нему выставлялись
счета; это отдельный, ранее согласованный показатель, и он по-прежнему
доступен на `/drones/`, `/drones/summary` и в выгрузках Excel.

Новый показатель живёт **рядом**, на отдельной странице `/drones/coverage`.

## 8. Запрет ложного числа

Число, пригодное для итоговой сводки, появляется только при статусе
`READY_ESTIMATE`. Во всех остальных случаях площадь равна `NULL`, **а не
нулю**: ноль читался бы как измеренное «ничего не обработано».

| Статус | Когда | Площадь |
|---|---|---|
| `READY_ESTIMATE` | вход полон, контур однозначен | число |
| `PARTIAL_DATA` | нет ширины на рабочем проходе или у части вылетов нет маршрута | `NULL` |
| `DATA_UNAVAILABLE` | маршрута нет ни по одному вылету работы | `NULL` |
| `CONTOUR_AMBIGUOUS` | два контура подходят одинаково | `NULL` |
| `CONTOUR_NOT_MATCHED` | ни один контур не совпал | `NULL` |
| `ROUTE_INVALID` | в сохранённом маршруте нет пригодной геометрии | `NULL` |

Никакого fallback: ни медианы, ни паспортной ширины машины, ни ширины
соседнего вылета, ни суммы, максимума или последней строки DJI.

Отдельная оговорка про ширину. Она «нужна» ровно там, где есть что
закрашивать: у маршрута без единого рабочего прохода рабочей полосы нет ни
при какой ширине. Поэтому её отсутствие у полностью холостого вылета **не**
делает число неполным и **не** превращает нулевой вклад в положительный.

## 9. Чего в этом документе нет

Ни одной настоящей координаты, ни одного идентификатора вылета, ни одного
UUID контура, ни cookie, ни токена, ни подписанной ссылки, ни содержимого
приватного capture. Приведённые здесь величины — агрегаты по выборке, по
которым исходные данные не восстанавливаются.
