# FIN-RECON-002 · Протокол утверждения заказчиков перед загрузкой книг

**Зачем.** Импорт книг сам заводит карточку на каждое незнакомое написание заказчика, всегда с типом `external` (`tools/import_drone_works.py`, `apply_rows`). Для июньских книг Ғиждувона и Шофиркона это 63 новые карточки. Протокол делает так, чтобы **каждое написание книг получило решение владельца**, механически и воспроизводимо. Решение получают и новые, и уже сопоставленные написания, и обобщённые «Фукаро». Импорт после этого не создаёт ничего сам.

**Инструменты (ветка FIN-RECON-002):**
- `tools/drone_import_alias_candidates.py` — строит таблицу из собственного разбора импортёра;
- `tools/drone_alias_decisions.py` — проверяет и применяет утверждённую таблицу;
- `tools/fin_recon_002_staging_check.py --decisions … --forbid-cards …` — репетиция всего окна.

## 0. Решения владельца от 27.10.2026, на которых стоит таблица

1. **«Заминлари» — одна организация.** Каноническая карточка №137 «Бухоро Агрокластер Заминлари МЧЖ»; №136 и №209 — старые варианты, не удаляются.
2. **«Гарден» — одна организация.** Каноническая карточка №155 «Гарден Бухоро Агрокластер МЧЖ»; №153 и №154 не сливаются.
3. **«Ғиждувон ПТЗ» — одна организация на все территории.** Одна новая карточка «Ғиждувон ПТЗ» (`internal`, номер назначит база). Пять новых написаний и уже сопоставленное с №690 написание ведут к ней. Территория остаётся в написании работы (`customer_raw` не переписывается). Карточки №684–692 ничего не получают и не меняются.
4. **«Фукаро» — не контрагент, а «гражданин».** Работы с обобщённым написанием хранятся без карточки, с отметкой `payer_unidentified` — правило импортёра `GENERIC_PAYER_KEYS`, не таблицы. Именные граждане («Жамшид (фукаро)») не блокируются.
5. **Внутренние работы платные**: тип `internal` ни одну сумму к получению не исключает.

## 1. Таблица решений

**Файл** `NEW_CUSTOMER_DECISIONS.csv`: UTF-8 с BOM, разделитель `;`. Его пишет `drone_import_alias_candidates.py` на **изолированной копии** полного бэкапа. **Одна строка — одно написание книг**, со статусом того, что импорт делает с ним сейчас.

| Колонка | Кто заполняет | Смысл |
|---|---|---|
| `normalized_key` | инструмент | машинный ключ = `customer_key()` импортёра. **Не править** |
| `new_card_name_as_imported` | инструмент | написание, как его сохранит импорт; перенос строки показан « ↵ » |
| `import_status` | инструмент | `CREATE` — импорт завёл бы карточку; `MATCHED` — алиас ведёт на `current_card_id`; `UNIDENTIFIED` — обобщённый гражданин, без карточки |
| `current_card_id`, `current_card_name` | инструмент | куда написание ведёт сейчас (для `MATCHED`) |
| `rows`, `area_ha`, `amount`, `tariffs`, `payment_types`, `source_sheets` | инструмент | что стоит за написанием |
| `source_rows` | инструмент | JSON-список `[файл, лист, строка]` всех строк написания |
| `holding_markers`, `hint`, `nearest_1..3` | инструмент | **подсказки**; сходство не доказывает тождество |
| `DECISION` | **владелец** | см. §2 |
| `TARGET_CARD_ID`, `TARGET_CARD_NAME` | **владелец** | id существующей карточки и её имя, как владелец его видел, — защита от подмены |
| `NEW_CARD_NAME` | **владелец** | имя одной новой карточки группы (`GROUP_NEW`, `REPOINT` в группу) |
| `NEW_CARD_TYPE` | **владелец** | `external` или `internal` |
| `CURRENT_CARD_ID` | **владелец** | куда написание ведёт сейчас — защита от изменения справочника |
| `EXPECTED_SOURCE_ROWS` | **владелец** | копия `source_rows`; для исключений (`REPOINT`, `UNIDENTIFIED`) обязательна |
| `NOTE` | владелец | комментарий, инструмент его не читает |

## 2. Допустимые решения

| `import_status` | `DECISION` | Нужные колонки | Что произойдёт |
|---|---|---|---|
| `CREATE` | `ALIAS` | `TARGET_CARD_ID` + `TARGET_CARD_NAME` | написание станет алиасом этой карточки |
| `CREATE` | `NEW` | `NEW_CARD_TYPE` | новая карточка с этим написанием и типом |
| `CREATE` | `GROUP_NEW` | `NEW_CARD_NAME` + `NEW_CARD_TYPE` | **одна** новая карточка на все строки с этим `NEW_CARD_NAME`; каждое написание группы — её алиас |
| `CREATE` | `HOLD` | — | не решено. **Запись всей таблицы отклоняется, импорт книг заблокирован** |
| `MATCHED` | `KEEP` | `CURRENT_CARD_ID` | остаётся там, куда ведёт алиас |
| `MATCHED` | `REPOINT` | `CURRENT_CARD_ID` + `EXPECTED_SOURCE_ROWS` + либо `TARGET_CARD_ID`/`TARGET_CARD_NAME`, либо `NEW_CARD_NAME` группы `GROUP_NEW` | **существующий** алиас переводится на другую карточку |
| `UNIDENTIFIED` | `UNIDENTIFIED` | `EXPECTED_SOURCE_ROWS` (+ `CURRENT_CARD_ID`, если у написания есть алиас) | работы ложатся без карточки, с `payer_unidentified = 1` |
| (ключ пуст) | `SET_TYPE` | `TARGET_CARD_ID` + `TARGET_CARD_NAME` + `NEW_CARD_TYPE` | у **существующей** карточки меняется только `customer_type` |

Любая другая заполненная колонка отклоняет таблицу (`E_EXTRA_FIELDS`). `--forbid-cards` перечисляет карточки, на которых не может оказаться ни одна строка книг. Для июня 2026 это `589,684-692,803`: обобщённые «Фукаро» и территориальные карточки ПТЗ. `ALIAS`, `REPOINT` или `KEEP` на такую карточку отклоняются (`E_TARGET_FORBIDDEN`).

**`REPOINT` переводит алиас, а не сохранённые работы.** Работы, которые уже лежат на старой карточке, остаются на ней. Так майская работа №690 остаётся на №690 (`tests/test_drone_alias_move_does_not_relink.py`). Перенос сохранённой работы — только адресная миграция с квитанцией, как перенос июньской работы 997 на №137.

**Тип `internal`** на суммы к получению не влияет: аудит `docs/FIN_RECON_002_FINANCE_RULE_AUDIT.md`, тест `tests/test_drone_internal_services_receivable.py`.

## 3. Матрица конфликтов (любая строка → вся таблица отклонена, код 1, ничего не записано)

| Код | Когда |
|---|---|
| `E_COLUMNS` | нет обязательной колонки |
| `E_DECISION` | значение `DECISION` не из списка |
| `E_DECISION_FOR_STATUS` | решение не допустимо для статуса написания: например, `ALIAS` для «Фукаро» или `UNIDENTIFIED` для именного гражданина |
| `E_DUP_KEY` | одно написание решено дважды или одна карточка переведена дважды |
| `E_KEY_NOT_NORMAL` | `normalized_key` не в нормальной форме импортёра |
| `E_KEY_UNKNOWN` | такого написания нет в книгах |
| `E_KEY_MISSING` | написание книг не решено в таблице (любого статуса) |
| `E_KEY_MIXED` | строки одного написания разрешаются по-разному |
| `E_ALIAS_TAKEN` | написание уже стало алиасом после построения таблицы |
| `E_TARGET_ID_FORMAT` / `E_TARGET_MISSING` | id не число / карточки нет |
| `E_TARGET_NAME` | карточка названа не так, как в таблице (переименована, другой id) |
| `E_TARGET_INACTIVE` | карточка выключена |
| `E_TARGET_FORBIDDEN` | строки книг оказались бы на карточке из `--forbid-cards` |
| `E_CURRENT_CARD` | написание ведёт сейчас не туда, куда записано в `CURRENT_CARD_ID` |
| `E_SOURCE_ROWS_FORMAT` / `E_SOURCE_ROWS_DIFFER` | `EXPECTED_SOURCE_ROWS` не JSON / строки книг не те |
| `E_REPOINT_TARGET` | у `REPOINT` нет цели, две цели или цель совпадает с текущей |
| `E_REPOINT_GROUP_UNKNOWN` | `REPOINT` в группу, которую таблица не создаёт |
| `E_GROUP_TYPE` | строки одной группы с разным типом |
| `E_TYPE` | нет типа `external` / `internal` |
| `E_EXTRA_FIELDS` | заполнена колонка, которую решение не принимает |
| `E_NEW_NAME_TAKEN` | `NEW` или `GROUP_NEW` с именем уже существующей карточки — решать `ALIAS` после доказательства тождества |
| `E_SET_TYPE_KEY` | у `SET_TYPE` заполнен `normalized_key` |
| `HOLD` | при `--apply`: есть нерешённые написания |

## 4. Что проверяется после изменения (dry run — на копии в памяти, `--apply` — внутри транзакции записи)

1. `drone_works` побайтно прежняя.
2. Карточки, которые были, побайтно прежние; у `SET_TYPE` меняется только `customer_type`.
3. Алиасы, которые были, побайтно прежние; у `REPOINT` меняется только `drone_customer_id`.
4. Новых карточек ровно `NEW + число групп`; новых алиасов — `NEW + ALIAS + написания групп`.
5. **Импортёр, запущенный заново против изменённой базы**:
   - читает те же строки, гектары и деньги;
   - не создаёт ни одной карточки, кроме `HOLD`;
   - каждую строку кладёт ровно туда, куда решено, а «Фукаро» — без карточки с отметкой;
   - ни одна строка не лежит на карточке из `--forbid-cards`.

Сухой прогон пишет `DECISIONS_DIFF.csv` и **`KEY_ROUTING.csv`** — матрицу «написание → карточка до → карточка после» со строками, гектарами и суммами. В `SUMMARY.txt` — итог по карточкам после изменения.

`--apply` выполняется одной транзакцией `BEGIN IMMEDIATE`:
- повторная проверка таблицы под блокировкой;
- изменения;
- постусловия;
- строка `schema_migrations` `DRONE_ALIAS_DECISIONS_<первые 16 hex SHA-256 таблицы>`;
- один `COMMIT`.

**Квитанция** двухфазная: `<receipt>.pending` до `COMMIT`, `<receipt>` и `<receipt>.diff.csv` после. Повтор той же таблицы — `ALREADY APPLIED`.

## 5. Порядок (всё до окна записи — только на изолированных копиях)

   ```powershell
   $backup = Get-ChildItem D:\transport-report-backups\production\daily\*.db | Sort-Object LastWriteTime -Descending | Select-Object -First 1
   ```

3. Решения владельца переносятся в таблицу. Для июня 2026 это делает частный сценарий пакета FIN-RECON-002 по двум рабочим книгам владельца. Каждая строка решения сверяется по строкам, гектарам и сумме. Имена карточек берутся из листов владельца, а не из базы. Автоматического выбора по сходству нет.
4. Репетиция с таблицей (одной строкой):

   **Когда `HOLD` нет**: ожидается `RESULT: PASS` (код 0) со строками «books -> 137 / 155 / PTZ / UNIDENTIFIED … owner decided …» и «no row of the books on a forbidden card».

   `SET_TYPE` в тип, который у карточки уже стоит, ничего не меняет, а повтор таблицы — `ALREADY APPLIED`.
5. Окно записи — только по отдельному разрешению владельца; пошагово — `docs/FIN_RECON_002_RELEASE_V132_RUNBOOK.md`. Порядок:

6. Копии баз из папок репетиции после чтения отчётов удалить.

## 6. Чего протокол не делает

- **Не перепривязывает уже сохранённые работы**, в том числе 7 майских работ на №589 и майскую работу на №690: май закрыт.
- **Не выбирает карточку по сходству.** Тест `test_a_similar_spelling_is_never_linked_to_the_similar_card_by_itself`.
- Не делает обобщённым ни одно написание: список `GENERIC_PAYER_KEYS` меняется только кодом с тестом и по решению владельца.
- Не сливает и не удаляет карточки (№136/209, №153/154, №684–692).
- Не меняет суммы, тарифы, поступления, тип оплаты, май и остальные месяцы.
