# VS-DJI-RC-COLLECTOR-001 — этап 0Б: безопасный план обследования пульта

**Это план, а не результат.** Ни одна строка ниже не описывает реальный
пульт: статус этапа — `WAITING_DEVICE / WAITING_SAMPLE`, пока владелец не
организовал доступ к согласованному пульту (ТЗ v1.1, §0.7, §6). Выполняет
владелец с ответственным оператором; облачная сессия к устройству и
внутренней сети доступа не имеет и не заявляет. Отчёт этапа 0А и карта
компонентов — `docs/DJI_RC_COLLECTOR_001_STAGE_0A.md`.

Выбранные здесь имена — реальные, а не плейсхолдеры: папка обследования
`C:\VehicleSoft_RC_Survey`, ярлык первого обследуемого пульта `RC-01`,
репозиторий на рабочей машине `C:\vehicle-soft`, ветка
`claude/vs-dji-rc-collector-stage-0a-bf38d3`. Если инвентарный ярлык
пульта в холдинге другой, он подставляется **во все** команды одинаково.

## 0. Правила, которые не нарушаются ни на одном шаге

Из ТЗ §4.2, §6.1, §0.6 и устава проекта.

- Всё — **на земле**, вне полёта, при включённом и не прерываемом DJI Agras.
  Ничего не ставится и не запускается на пульте, пока борт в воздухе.
- Не делать root, не менять прошивку, не обходить защиту, не включать
  небезопасные настройки, не выполнять factory reset, не обновлять прошивки
  ради доступа.
- Ничего не удалять, не перемещать, не переименовывать на пульте; память не
  чистить. Копирование — только **с** пульта **на** компьютер.
- `DRONE_API_TOKEN` на пульт не ставится; ничего не отправляется в
  `POST /drones/api/source_sync`, `route_sync` и другие приёмники; боевая
  база и площадка не трогаются.
- Внутренний HTTP наружу не публикуется, проверка сертификатов не
  отключается, сетевые настройки пульта и предприятия не меняются.
- Секреты (пароли, токены, подписанные ссылки) не печатаются, не
  пересылаются, не кладутся в репозиторий и отчёты. Файл с маркером секрета
  инструмент помечает и в снимок по умолчанию не копирует — его судьбу
  решает владелец отдельно.
- Снимки экрана — только вручную, на земле, при необходимости.
- Искусственная или частичная передача доказательством доступа к данным
  DJI не является; GO выносится только по реальному полезному объекту.

Три проверки доступа (§3.1 USB, §3.2 штатный экспорт, §3.3 обычное
приложение) — **три разных ответа**; один не заменяет другой (ТЗ §6.2).

## 3. Три раздельные проверки доступа

### 3.1. USB с компьютера (режим чтения)

1. Подключить пульт кабелем USB-C к рабочей машине; на пульте выбрать режим
   передачи файлов, если он предлагается. Ничего не форматировать.
2. В Проводнике Windows открыть устройство. Записать в `passport.md`:
   видны ли папки верхнего уровня (перечислить имена), видна ли `Android`
   и `Android\data`, есть ли папки с именем `DJI` или именем пакета
   приложения.
3. Скопировать **перетаскиванием** в `C:\VehicleSoft_RC_Survey\RC-01\raw\usb\`
   всё, что видно и относится к DJI (папки `DJI*`, `Android\data\dji.*`,
   `Download`, `Documents`). Если объём велик — сначала только папки DJI.
   Файлы на пульте не удалять. Если Проводник показывает пустое
   устройство или ошибку доступа — записать это как результат, не искать
   обход.
4. Опись (ничего не пишет в `raw`):

```powershell
& "C:\Program Files\Python314\python.exe" C:\vehicle-soft\tools\dji_rc_probe.py inventory C:\VehicleSoft_RC_Survey\RC-01\raw\usb --out C:\VehicleSoft_RC_Survey\RC-01\probe\usb --device-label RC-01
```

Код выхода: `0` — опись готова; `1` — файлов нет; `3` — есть файлы с
маркером секрета (опись готова, эти файлы не пересылать); `4` — папка
вывода внутри источника (не бывает при этих путях).

### 3.2. Штатный экспорт

**а) DJI Agras.** На пульте найти в приложении экспорт или «поделиться»
для записей полётов / журналов (если есть). Экспортировать на microSD или в
общую папку, затем перенести по USB в `raw\app_export\`. Записать: есть ли
такая функция, сколько действий требует, куда пишет, какие файлы получились.
Если функции нет — это результат.

**б) DJI Assistant 2 for MG.** Только если владелец решил его ставить.
Подключить пульт по USB-C, в DJI Assistant открыть раздел журналов, выбрать
журналы пульта и экспортировать в `raw\assistant\`. Если программа
предлагает журналы борта — экспортировать их в подпапку `raw\assistant\aircraft\`.
Записать: требуется ли вход в аккаунт DJI, какие файлы и расширения
получились, их размеры, сколько времени занял экспорт.

Опись каждой папки:

```powershell
& "C:\Program Files\Python314\python.exe" C:\vehicle-soft\tools\dji_rc_probe.py inventory C:\VehicleSoft_RC_Survey\RC-01\raw\app_export --out C:\VehicleSoft_RC_Survey\RC-01\probe\app_export --device-label RC-01
```
```powershell
& "C:\Program Files\Python314\python.exe" C:\vehicle-soft\tools\dji_rc_probe.py inventory C:\VehicleSoft_RC_Survey\RC-01\raw\assistant --out C:\VehicleSoft_RC_Survey\RC-01\probe\assistant --device-label RC-01
```

### 3.3. Обычное приложение (без установки на этом шаге)

На этапе 0Б **ничего не устанавливается**, пока нет результатов 3.1–3.2 и
отдельного решения владельца. Сейчас — только наблюдение (записать в
паспорт): разрешена ли установка из неизвестных источников (не включать),
есть ли штатный системный выбор папки (Files / «Документы»), видна ли из
него папка, в которой по 3.1 лежат файлы DJI.

Если владелец решит идти дальше, минимальный диагностический APK — отдельный
инкремент со своим PR. Его границы, чтобы решение было предметным:

- делает: системный выбор папки пользователем; список файлов выбранной
  папки с размером и SHA-256; запись одного JSON-манифеста в собственную
  папку приложения; показ манифеста на экране; удаление приложения штатно;
- не делает: не запрашивает «управление всеми файлами», не читает
  `Android/data` чужих приложений, не работает в фоне, не ходит в сеть, не
  трогает DJI Agras, не хранит и не передаёт секретов;
- проверяется: установка штатным способом, работа рядом с запущенным
  Agras на земле, штатное удаление; результат — тот же манифест, что даёт
  `snapshot` на компьютере, и совпадение хешей файла, прочитанного
  приложением, и файла, скопированного по USB.

### 3.4. Сеть (только наблюдение)

Записать: подключён ли пульт к Wi-Fi предприятия или к мобильной сети;
доступен ли с него интернет (например, открывается ли страница DJI в
браузере пульта, если он есть). **Не проверять** доступность
`10.103.25.14` и не менять сетевые настройки: маршрут от пульта к тестовой
среде проектируется отдельно (VPN или TLS-шлюз, ТЗ §10).

## 4. Снимок и сравнение с облаком

### 4.1. Снимок в изолированную папку с проверкой хешей

```powershell
& "C:\Program Files\Python314\python.exe" C:\vehicle-soft\tools\dji_rc_probe.py snapshot C:\VehicleSoft_RC_Survey\RC-01\raw C:\VehicleSoft_RC_Survey\RC-01\snapshot --device-label RC-01
```

Ожидается `status=OK`, `verify_failed=0`; манифест —
`C:\VehicleSoft_RC_Survey\RC-01\snapshot\manifest.json` (происхождение `RC`,
SHA-256 каждого файла, время изменения источника, время захвата). Файлы с
маркером секрета остаются в `raw` и перечисляются в `skipped`. Код `5`
(`VERIFY_FAILED`) — копия не совпала с источником: повторить, не пересылать.

### 4.2. Если опись показала файлы, похожие на V4 (`v4_like > 0`)

1. Выписать из `inventory.md` окна этих файлов (`t_first_ms`, `t_last_ms`) и
   найти в кабинете SmartFarm вылеты этого борта за тот же день; записать
   их `dji_flight_id` в `C:\VehicleSoft_RC_Survey\RC-01\cloud_v4\ids.txt`
   (по одному в строке).
2. С рабочей машины сборщика (там, где сохранена сессия DJI, venv
   `drone_collector\.venv`) выполнить **существующий** адресный захват
   облачных источников этих вылетов в режиме сухого прогона — ничего не
   отправляется, тела остаются в очереди/дампе сборщика:

```powershell
Set-Location C:\vehicle-soft
```
```powershell
drone_collector\.venv\Scripts\python.exe -m drone_collector.main --sources --ids-file C:\VehicleSoft_RC_Survey\RC-01\cloud_v4\ids.txt --dry-run
```

   Режим, его коды выхода и место, куда ложатся тела, описаны в
   `drone_collector/README.md`, раздел «Collect the immutable DJI sources»
   (выполняется в день, свободный от ежедневного цикла; площадку не
   трогать). Тело V4 каждого вылета скопировать в
   `C:\VehicleSoft_RC_Survey\RC-01\cloud_v4\<dji_flight_id>.bin`.
3. Сравнить каждую пару «файл пульта — облачный V4»; имя файла пульта берётся
   из `inventory.md`:

```powershell
& "C:\Program Files\Python314\python.exe" C:\vehicle-soft\tools\dji_rc_probe.py compare-v4 C:\VehicleSoft_RC_Survey\RC-01\snapshot\usb\example_from_inventory.bin C:\VehicleSoft_RC_Survey\RC-01\cloud_v4\673501214.bin --json C:\VehicleSoft_RC_Survey\RC-01\probe\compare_673501214.json
```

   В этой команде `example_from_inventory.bin` и `673501214` заменяются на
   реальные имя файла и `dji_flight_id` из шага 1 — это единственные два
   значения, которые план не может назвать заранее.

   Инструмент отвечает: совпали ли байты (`identical_bytes`), число кадров с
   одинаковым временем, сколько из них с одинаковыми битами счётчика,
   шириной, флагом распыления, позицией; какие ключи есть только с одной
   стороны. **Совпадение окон — не доказательство того же вылета** (V4 не
   несёт flight id); совпадение байтов доказывает одинаковую копию, не
   подлинность DJI.

|---|---|
| В описи `SECRET_MARKER` | файл не пересылать, в снимок не включать; факт — в отчёт; дальше — решение владельца |
| Файл помечен `RECENTLY_MODIFIED` или растёт | подождать ≥ 60 с без изменений размера и времени, повторить копирование и опись; обе версии сохранить как разные объекты |
| `SQLITE_WAL_OR_JOURNAL_PRESENT` | копия базы может быть неконсистентной; записать `INCONSISTENT_SOURCE`; искать штатный экспорт |
| `ZIP_PATH_TRAVERSAL` / `ZIP_EXECUTABLE_ENTRY` | архив не распаковывать; перечень записей — в отчёт |
| `UNKNOWN_BINARY` без переписи protobuf | формат неизвестен; не называть ничем; перепись и размеры — в отчёт |
| Файл похож на V4, но окно не сходится ни с одним вылетом | неопределённость, не связь; записать окно и борт |
| Проводник не видит устройство или папки | результат проверки 3.1; не искать обход |
| `snapshot` вернул `VERIFY_FAILED` | повторить снимок в новую пустую папку; не пересылать |

## 9. Чего на этапе 0Б не делается

Приёмник и таблицы для `RC`, миграции, изменение сборщика и его
расписания, изменение площади, решений, отчётов и финансов, отправка в
боевые приёмники, сетевые настройки, прошивки, установка APK без отдельного
решения владельца, полноценное приложение. Всё это — после рассмотрения
результатов 0Б (ТЗ §0.7, §16).
