# PLAN.md — сводный план работ по четырём модулям

> Единственный документ, где четыре трека сведены в один порядок. Ведёт его
> диспетчерский чат. Трековые чаты сюда не пишут — у них
> `docs/tracks/<трек>.md`.
>
> **Здесь нет состояния площадок.** Что где развёрнуто — в верхнем блоке
> `docs/AGENT_STATE.md` и в выводе `tools/state_snapshot.py`.
>
> Редакция от 2026-07-29.

---

## 1. Зачем этот документ

До 2026-07-29 четыре трека — Запчасти, АЗС, GPS план-факт, Дроны — велись в
четырёх независимых чатах. Каждый новый чат тратил первую пятую часть контекста
на выяснение состояния, доки расползались, а очерёдность работ между модулями
не выстраивал никто. Консолидация свела планирование в один контур; этот файл —
его результат.

**Порядок задаёт не важность модуля, а зависимость.** Сначала то, на чём стоит
всё остальное; потом то, что растёт вверх независимо; потом то, что связывает
выросшее.

**Разработка и сбор данных — два независимых потока.** Три трека независимо
записали в свои handoff «пока данных нет, начинать бессмысленно». Это неверно:
данными заблокировано применение, а не разработка. Код фазы 3 АЗС пишется на
синтетической тарировке, конвейер GPS — на уже собранных `calib_tracks.csv` и
`verify_tracks.csv`. Сбор запускается в день 1 и идёт неделями сам по себе.
Раздел 7 — самый важный в этом файле.

**Один промпт Fable ≠ один PR.** Промпт описывает N упорядоченных PR со своими
критериями приёмки и своим откатом. Для владельца это одно делегирование, для
ревью — обозримые диффы.

## 2. Принятые технические решения

Меняются только по новым фактам, с записью причины.

| № | Решение | Основание |
|---|---|---|
| Т1 | Ёмкости АЗС — `FuelWarehouseTank` / `fuel_warehouse_tanks` | `FuelTank` и `fuel_tanks` заняты мёртвой v1-моделью, привязанной к `fuel_stations` (`models.py:496`) |
| Т2 | Один справочник контуров `field_contours` с дискриминатором источника | GPS зеркалирует 17 812 геозон Wialon, Дроны собирают 4 776 полей DJI — иначе два справочника одного и того же |
| Т3 | Сырые точки GPS — окно 90 дней в отдельном хранилище; полигоны и площади — навсегда в основной БД | ~1 млн точек в сутки; защитимый артефакт для счёта — полигон, а не точка |
| Т4 | `wialon_id` добавлен в `vialon_mappings`, `vialon_name` оставлен | Имена в Wialon меняются, шесть номеров указывают на несколько объектов, одна машина существует тремя объектами |
| Т5 | `_perform_fuel_sync` не трогается; общий помощник `ingest_common.py` строится рядом | Рефакторинг живого тракта приёма не стоит риска |
| Т6 | Мёртвые v1-таблицы топлива не удаляются | Разрушающая миграция ради красоты имени не оправдана |
| Т7 | Дефекты, найденные фундаментальным PR, сообщаются, но не чинятся в нём же | Фундаментальный PR не должен везти изменения поведения — иначе его не откатить одним движением |

## 5. Фаза 2 — модули в высоту. **СЛЕДУЮЩАЯ**

Один промпт Fable, две независимые цепочки: по файлам они не пересекаются и
мержатся отдельно. Общие у них только три файла доков — там правило прежнее:
одна строка на запись, дописывать в конец своей секции, таблицу не
переформатировать.

### Цепочка A — новые модули

**DRONE-001 — фундамент.** `drone_units` (15 машин, ключ — номер, исключение из
отчётности флагом с датой), `drone_nicknames` (19 алиасов, пополняемая),
`drone_flights` (ключ — id вылета DJI, хранить `raw_json`), `drone_sync_logs`.
Все машины на `organization_id = 12`. Единицы нормализуются из сырых полей:
`new_work_area` м² → га, `spray_usage` мл → л, `sow_usage` **граммы** → кг,
таймстемпы unix UTC → показывать UTC+5. **Числа с экрана и из экспорта не
брать** — там гектары, mu и снова mu без подписи.

**DRONE-002 — приёмный endpoint** на `ingest_common`. Пишется и проверяется на
`raw_json` из старой `app.db` (10 385 вылетов) — от сборщика не зависит, можно
вести параллельно с DRONE-003.

**DRONE-003 — сборщик.** Playwright, служба под доменной учёткой (не
`LocalSystem`: Chromium ставится в профиль пользователя — самая частая ошибка в
логах старого сборщика). Управление периодом с проверкой возвращённого
диапазона, проверка региона после входа, повтор и watermark. Исторический сбор —
годовыми окнами: период не уезжает в URL и календарь сбрасывается через границу
года. Зависимости сборщика в серверный `requirements.txt` не попадают.
Приёмка: прогон `2026-01-01 → сегодня` сходится с плиткой SmartFarm по вылетам
и гектарам.

**DRONE-004 — экраны только на чтение.** Список вылетов, карточки машин, сводка,
разрез по областям и районам, Excel. Серверная пагинация обязательна с первого
дня: в сезон 150 вылетов в день, пик 476.

**GPS-1 — приём и хранилище.** Пулл по Wialon Remote API (не ретранслятор — у
нашего сервера нет публичного адреса), watermark, хранилище точек вне
`instance\transport.db` по решению Т3.

**GPS-2 — расчёт площади.** Метод зафиксирован и не пересматривается: точки
1–15 км/ч и внутри контура → сгущение пути каждые 5 м → альфа-форма по Делоне с
альфа = 10 м → объединение → обрезка по контуру → площадь в UTM 41N
(EPSG:32641). Обязательные части: определение контура **по треку** (по имени
нельзя — «1508 Нурхон Бобохон» это две разные зоны, 4,32 и 8,97 га), флаг
качества расчёта, страховка при совместной работе — считать рядом объединение
полигонов и помечать пересечение, если сумма его превысила. Адаптивная альфа
`max(10; 1,2 × шаг)` в метод **не вводится**: подобрана на тех же данных.

**GPS-3 — зеркалирование контуров** в `field_contours`: 17 812 геозон ресурса 285.

### Цепочка B — добивание существующих модулей

**F3.1 — ёмкости и тарировка.** `FuelWarehouseTank` (решение Т1),
`FuelTankCalibration`. Пересчёт — линейная интерполяция, **без экстраполяции**
за границами таблицы. Импорт из Excel, график для глаза, проверка монотонности.

**F3.2 — замер и сеанс инвентаризации.** `FuelInventorySession` — основная
сущность: складов с несколькими ёмкостями больше, чем с одной. Сеанс завершён,
только когда замерены все активные ёмкости склада. Хранятся **и сантиметры, и
литры**. Время с точностью до минуты и автор каждого замера.

**F3.3 — отчёт сверки.** Излишек или недостача, **без нормы расхождения**.
**Замер ничего не переписывает.** Печатная форма с местом для подписей.

**F4.4 + FUEL-CARDS-SYNC — единственный рискованный PR фазы.** Трогает тракт
приёма. Карта данных Topaz готова: статус карты не в `dcCards.Enabled`, а в
`dcLimitRestrictions.LimitTypeID` при `AmountID = 2`; остаток карты =
`SUM(rgAmountRests."Rest")`; псевдокарту `CardID = 0` исключать обязательно;
моточасы из Topaz не придут. **Совместимость обязана быть двусторонней.**
`topaz_agent.py` в git не хранится — отдаётся файлом, владелец переносит с
бэкапом на `10.103.40.140`.

**Запчасти — дешёвые доделки.** `SP-PICKER-SEARCH-001` (бэкенд готов:
`/api/catalog-search` с `difflib` и дебаунсом, нужна обвязка трёх подборов),
`SP-STOCK-XLSX-001`, `SP-SKU-XREF-DUP-001` — **предупреждение, а не
ограничение**. Плюс экранирование ведущего `=` во всех выгрузках `openpyxl`.

### Разделение проверки в фазе 2

Браузерный агент: списки, карточки, фильтры, пагинация, доступность страниц,
ACL на чтение, языки, отсутствие латиницы в узбекском.
Владелец руками — всё, где есть запись: приём вылета через endpoint, прогон
сборщика, импорт тарировочной таблицы, ввод замера и закрытие сеанса, прогон
синхронизации карт, три подбора запчастей.
Отчёт агента без объёма данных («N позиций ОК») не принимается.

## 9. Уроки метода, полученные дорого

- **Проверка, у которой «успех» и «полный отказ» выглядят одинаково, проверкой
  не является.** Нужен положительный контроль. Пустой ответ эндпоинта, пустой
  вывод чекера, отсутствие кнопки на карточке — всё это требует второго
  измерения, доказывающего, что инструмент вообще работает.
- **Отчёт агента — заявка, а не доказательство.** Чекер шаблонов принят только
  после независимой пробы из десяти планированных дефектов и безопасных
  двойников.
- **Копии файлов устаревают молча.** Расхождение по `RELEASE_GATE.md` оказалось
  не потерей строки при мерже, а копией, снятой на два коммита раньше.
- **Ущерб оценивается по факту, а не по аналогии.** Гипотеза, что экран прав
  снёс у учётки `transport` и `deficiencies`, не подтвердилась: копия staging
  показала, что этих прав не было никогда.
- **Устав тоже может быть неверен.** Утверждение «файлы в git имеют CRLF»
  ошибочно: в репозитории LF, CRLF появляется в рабочей копии через
  `core.autocrlf`.
